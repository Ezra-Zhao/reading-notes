## 一句话核心观点

**前五篇讲的检索与生成，到了这一节要落成一套能跑的系统：框架先选——LangChain 是全能工具箱（六大模块，什么都管），LlamaIndex 是检索专才（索引与查询见长、大数据量更利落），两者还能搭着用；搭法就五步——装框架、加载文档、按 1000 字一块、重叠 200 字切开、编码进向量库，再把检索器与生成器用一条链串起来，问题进来先捞文档、文档连问题一起交给模型、答案出去。系统搭好之后看它往哪儿长：长进智能体里，它是记忆、计划、行动三个模块共同的信息后勤；长进医疗这类垂直领域里，它得先学会把影像与文本两种模态融在一起检索，单看哪一种都可能排错。一句话：RAG 的终点不是一篇方法，是一套有框架、有流水线、有落地场景的工程。**

## 详细解读

### 1. 为什么先讲框架：手搓太慢，现成的轮子已经齐了（6.5 开头与 6.5.1 开头）

教材对 6.5 的定位很直白：RAG 能缓解幻觉、拓展知识边界，性能好、关注度高，已经在众多场景落地，本节讲两件事——怎么搭一套简单的 RAG 系统，以及它的两类典型应用。搭系统不从零手搓：已有诸多成熟开源框架，最具代表性的是 LangChain 与 LlamaIndex。它们提供完备的工具与接口，让开发者能把 RAG 集成进聊天机器人、智能体等应用里。下面先比框架，再用其中一个把系统搭出来。

### 2. 两大框架分工：一个全能，一个专才（6.5.1 其一，书 272）

LangChain 旨在简化用大语言模型开发应用的整个过程，提供模块化组件，含六大模块。Model IO 管各种大模型的接口与提示设计；Retrieval 是构建 RAG 的核心组件所在，含文档加载、文本分割、向量构建、索引生成与向量检索，还提供非结构化数据库接口；Chains 把各模块链接起来逐个执行；Memory 存储对话过程中的数据；Agents 让大语言模型自动决定执行哪些操作；Callbacks 帮开发者干预与监控各个阶段。教材总评：模块支持较为全面，能轻松便捷地构建 RAG 应用框架。

LlamaIndex 与之相比更专注数据索引与检索：能从 API、PDF 文件、SQL 数据库等多种数据源提取数据，提供向量化与索引构建工具，查询侧有高效检索机制，拿到上下文后还支持过滤、重新排序等精细化操作；它还能与 LangChain 结合实现更多样功能。教材总评：侧重索引与检索、查询效率表现更突出，非常适合在大数据量场景下构建更高效的 RAG 系统。选型口径就此清楚：要一站式全家桶选前者，要把检索这一段做到极致、数据量又大，选后者或让后者专管检索段。

### 3. 搭系统五步（上）：装、加载、切块、建索引（6.5.1 其二，书 273–274）

教材以 LangChain 官方文档为参照演示，步骤如下。第一步安装与配置：装 LangChain 本体及社区包、Chroma 集成包。第二步数据准备与索引构建，又分三小步。加载：DocumentLoaders 提供种类丰富的文档加载器，示例用 WebBaseLoader 从网页加载内容并解析为文本。切块：加载出的文档可能过长、不适合模型的上下文窗口，用 RecursiveCharacterTextSplitter 分割，示例参数是每块 1000、相邻块重叠 200——重叠的用意是别让一句话正好断在块边界上丢了上下文。建索引：把切好的块交给 Chroma 向量存储、用 OpenAIEmbeddings 嵌入模型编码存储，以便后续按向量相似性检索。我的脚本把切块这一步缩小复算了一遍：27 字玩具文档按每块 10 字、重叠 3 字切成 4 块，相邻块确实共享重叠段、末块收全尾巴；参数放大到教材的 1000/200，道理同一条。

### 4. 搭系统五步（下）：检索器、生成器、一条链（6.5.1 其二，书 274–275）

索引建好，开始组装系统本体，它由检索器与生成器两部分构成，工作流程是：问题进来，检索器先搜相关文档，文档与原问题一起传给生成器（大语言模型），答案返回用户。检索器由向量存储经 as_retriever 一步得到，按向量相似性检索。生成器示例用 ChatOpenAI，需设置 OpenAI 的 API 密钥并指定模型型号，教材选的是 gpt-3.5-turbo-0125。提示模板不自己写：从 LangChain 的 Prompt Hub 拉取适用于 RAG 任务的预设模板 rlm/rag-prompt。最后用 LangChain 表达式语言 LCEL 组链：context 一路由检索器接一个文档格式化函数（把多篇文档的正文以空行拼成一段），question 一路由 RunnablePassthrough 把原问题原样直通，两路汇入提示模板，再依次过语言模型与字符串输出解析器。教材的示例调用问的是 "What is Task Decomposition?"。我的脚本用纯标准库把这条链的骨架复刻了一遍：执行轨迹严格是检索、格式化、组提示、过模型、解析五步，context 与 question 两路在提示处汇合；同时把极简全链跑通——问考拉睡多久吃什么，检索回的正是讲考拉睡眠与桉树叶的文档、答案只出自这段上下文；换问袋鼠，检索与答案随之换；问库里没有的火星问题，玩具生成器明确回「没有依据、不编造」。链的顺序与有据的边界，都验到了。

### 5. 典型应用一：RAG 长进智能体里，当三个模块的后勤（6.5.2 其一，图 6.27）

教材介绍的经典 Agent 框架出自 Wang 等人的大语言模型自主智能体综述，由四大部分组成：配置、记忆、计划、行动，其中记忆、计划、行动三个模块都融入了 RAG。配置模块设定 Agent 的基本信息来定义角色：年龄、性别、职业等基本属性，以及反映个性与社交关系的信息。记忆模块存储从环境学到的知识与历史信息，支持记忆检索、记忆更新与记忆反思，让 Agent 不断获取、积累与利用知识，RAG 在此辅助记忆的读取与更新。计划模块把复杂任务分解为简单子任务，并根据记忆与行动反馈不断调整，RAG 在此提供相关信息帮它更合理有效地规划。行动模块把计划转化为具体行动，包括网页检索、工具调用与多模态输出，能影响环境或 Agent 自身状态、或触发新的行动链，RAG 在此辅助决策与行动执行。一句话：Agent 负责想与做，RAG 负责在它想与做的每一步把对的信息递到手边。

### 6. 抱考拉全流程：五步看清四模块怎么协同（6.5.2 其一，图 6.27 续）

教材的例子是：用户现在在澳大利亚，想去抱考拉，怎么办。处理分五步。角色配置：Agent 初始化为专业的旅游顾问（图 6.27 的配置格写的是熟悉澳洲生活的向导），目标是协助用户实现与考拉亲密接触的愿望。任务规划：计划模块规划三件事——确定当前位置附近存在考拉的地点、了解当地与野生动物互动的法律规定、考虑前往目的地的方式；这一阶段 RAG 提供旅游景点与法律法规信息，使规划更精准。信息检索：记忆模块先在记忆中检索已有相关信息（图中的记忆格里存着科伦宾野生动物保护区可以合法拥抱考拉），记忆里不全的，行动模块激活并调用工具从旅游网站等外部知识源检索，RAG 保证以最高效率捞到最相关的信息。信息整合与决策：计划模块用检索到的信息制定最佳行动方案，可能涉及推荐特定地点、提供出行建议、强调安全须知，RAG 在此整合信息辅助决策。信息输出：行动模块把方案以易于理解的方式输出，包括详细的路线规划、相关地点的描述与图像等。图中给出的推荐是：用户在昆士兰州，可去布里斯班的龙柏考拉动物园，或黄金海岸的科伦宾野生动物保护区与天堂农庄。我的脚本把这条流程做成状态机复算：计划三步里有两步记忆未命中、触发外检，最终输出包含龙柏与科伦宾两处——五步的衔接关系对得上。

### 7. 典型应用二：垂域多模态——先融合，再检索（6.5.2 其二，图 6.28）

前面各节的 RAG 都在文本领域打转，垂直领域里数据往往是多模态的。以医疗为例：X 光片、MRI、CT 扫描等影像资料，加上病历、生理监测数据等文本资料，来源广泛、彼此之间存在复杂的相互联系，RAG 系统必须具备融合与洞察不同模态数据的能力，才能精准高效。教材举 Ossowski 等人提出的医学领域多模态检索框架为例，流程三段：先提取图像与文本的特征表示，深入理解图像内容与问题语义，为检索提供丰富的特征向量；再由精心设计的多模态检索模块，用这些特征向量在医学知识库中精准检索最相关的信息，这些信息可能包括医学案例、症状描述、潜在病因与治疗方案，形式有文本也有图像；最后由 Prompt 构建模块整合信息，辅助模型生成准确回答。示例任务是给一张 X 光照片、问它对应的可能症状，框架生成的答案是「心肌肥大」，图 6.28 中生成侧画的是 T5 编码器与解码器。我的脚本把融合的必要性做成最小演示：三个玩具病例里，只按图像距离排会选中一个错例、只按文本距离排会选中另一个错例，两个距离相加融合后才命中正确例——单模态各有一只眼，合起来才看全。

### 8. 收尾：RAG 的版图与第六章的终点（6.5.2 其二结尾）

教材最后把版图再摊开一格：除医疗外，RAG 在金融、生物学等垂直领域也展现了处理专业信息的强大能力，显著提升专业人士的决策效率；在模态上，除图片外，RAG 在音频、视频等其他多模态场景中同样有出色表现。展望只有一句：随技术进步与数据资源丰富，期待 RAG 在更多垂直领域、更多数据模态中发挥关键作用。至此第六章收尾：从为什么要外接图书馆（6.1）、黑盒白盒怎么协作（6.2）、库怎么建问题怎么问（6.3）、料怎么用才不浪费（6.4），到这一节的搭系统与两类落地——RAG 的完整链条闭环。本系列拆书也到此全书拆完：六章、三十二篇，从 n-gram 一路走到能落地的 RAG 系统。

## 我的思考/应用

- **先选框架分工，再写第一行代码。** 这一节最实用的不是某段代码，是选型口径：全流程一站式与检索专才本是两种产品形态，硬用全能箱做海量检索、或硬让专才管对话与行动，都会在后期返工。我们自己搭任何问答与知识系统同理：先按数据量与检索复杂度定分工，再动手。（成本：选型要先花时间摸清两边边界；收益：避免系统长大后推倒重来；证据 B，两框架的模块构成与定位均为教材原文，分块与组链经本篇脚本演示）
- **切块参数是知识系统的地基，不是默认值。** 1000 与 200 这对数字背后是两笔账：块太大塞不进上下文、检索回一整段噪声，块太小把一句话切碎、答案的依据散在几块里谁也捞不全。重叠段是专门为边界处的信息买的保险。任何要落地的检索系统，上线前都该拿自己的真实文档试切几组参数、看检索结果，而不是抄教程默认值。（成本：调参要拿真实问题集反复试；收益：检索质量在源头就定住，后面换模型也补不回来；证据 B，切块动机与示例参数为教材原文，重叠的覆盖效果经本篇脚本逐字演示）
- **Agent 的本事不在模型，在信息后勤。** 抱考拉例子里，模型本身没有变聪明，变的是四件事的衔接：角色先定清、计划先拆开、记忆先查、外检补缺、最后整合输出。RAG 在三个模块里出现的共同角色是「把对的信息在对的步骤递到手边」。我们做任何自动化助手都该照这个顺序查：不是先问模型够不够强，而是先问每一步需要的信息有没有通道送达。（成本：记忆、检索与整合三条通道都要单独建设与维护；收益：系统能力随知识通道扩展，不必等模型升级；证据 B，四模块构成、RAG 的三处介入与五步流程均为教材原文，流程衔接经本篇脚本演示）
- **垂域落地先过模态这一关。** 医疗例子给的提醒是通用的：专业领域的数据天然多模态，影像、文本、监测数值彼此关联，只接一种模态的系统在真实场景里会系统性地排错。做垂域应用，立项时就该把模态清单列全、融合方式定好，而不是先做一个纯文本版再说。（成本：多模态的特征提取与融合检索工程量明显更大；收益：避开单模态的系统性盲区；证据 B，多模态数据的构成、融合检索框架三段流程与 X 光示例均为教材原文，融合改变排序经本篇脚本演示）

## 视频脚本要点（动画短片用）

1. 开场钩子：讲了五篇检索与生成，这一篇不讲道理了，直接开工——把图书馆、管理员和写作者装进一台真机器，看它第一次开口答题。
2. 工具箱动画：两个工具箱并排打开，一个格子多到六层、什么活都接，另一个只有一层却全是检索的家伙；镜头一转，第二个箱子被嵌进第一个箱子里一起干活——全能与专才，原来能搭着用。
3. 切块动画：一卷长纸被剪成一千字一张的纸条，每张纸条的尾巴都和下一张重叠一截，纸条被逐张贴上编号存进抽屉墙——问题来了，抽屉按相似度自己弹开两格。
4. 流水线动画：问题从左边进传送带，先被捞文档的机械手配上两页资料，资料与问题在中间汇合、被装进一个信封递给写作者，写作者照着资料写完，末端盖章出厂——五个工位，一个不多。

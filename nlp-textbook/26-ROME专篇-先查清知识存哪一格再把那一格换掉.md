# NLP 读书笔记（26）：ROME 专篇——先查清知识存哪一格，再把那一格换掉

> 来源：中文 NLP 教材（浙江大学），《Foundations of LLMs》讲义第五章 5.4 节
> 覆盖：书页码 211–219（5.4.1 知识存储位置：因果跟踪与阻断实验；5.4.2 知识存储机制；5.4.3 精准知识编辑，式 5.15–5.21，图 5.12–5.20）· 本篇为 clean-room 重写，例题与代码均为自编并已运行验证

## 一句话核心观点

**ROME（秩一模型编辑）的顺序与上一篇的 T-Patcher 正好相反：不先动手改，先花两组实验查清知识到底存在哪里——因果跟踪圈出中间层在处理主体最后一个 Token 时的位置，阻断实验再把功劳判给全连接前馈层而不是注意力层；定位之后才编辑，三步走完：用多个随机前缀平均出键向量 k*（式 5.15），用准确性加局部性的两项损失优化出值向量 v*（式 5.16–5.18），最后把插入新键值对写成带约束的最小二乘问题，闭式解给出的更新恰好是一个秩一矩阵（式 5.19–5.21），方法名就来自这里。它在表 5.2 里四项全高，但只管知识元组形式的单条事实、不支持批量编辑，批量是后续 MEMIT 的事。**

## 详细解读

### 1. 先定位：因果跟踪三步——正常、干扰、逐个恢复

要改一个知识点，先得知道它存在哪。ROME 的第一组实验叫因果跟踪，思路是控制变量：先把正常状态存下来，再人为弄坏，然后逐个位置恢复，看恢复哪一处最能把答案救回来。

研究对象先被写成知识元组 t=(s, r, o)：s 是主体，r 是关系，o 是客体。比如「斑马的肤色是黑色」就是（「斑马」，「的肤色是」，「黑色」），送进模型的问题是 q=(s, r)，期望输出是 o。三步是：第一步正常推理，把 q 输入模型、保存所有模块的正常输出；第二步干扰推理，只在主体 s 的嵌入层输出上加噪声，把内部状态弄乱，模型这时答不出原来的答案；第三步恢复推理，在干扰状态下，把每个 Token 在每一层的输出逐个、独立地恢复成正常值，其余位置保持干扰，每恢复一处就记录答案概率涨了多少，这个增量就叫该位置的因果效应。

教材给的规模是 1000 个知识陈述、三种模块（Transformer 层整体、前馈层、注意力层）分别统计。结论有两层。第一层：中间层 Transformer 在处理主体最后一个 Token s(-1)（例子里是「马」）时因果效应显著。末尾层在处理问题最后一个 Token q(-1) 时效应也很强，但教材自己点明这不意外——那个位置贴近输出，效应大不等于知识存在那里。第二层是下一节阻断实验要确认的：在 s(-1) 处的效应里，主要贡献来自全连接前馈层。我的脚本用玩具概率把「效应等于恢复后概率减干扰概率」这个定义和上述排序复算了一遍，玩具数值只演示定义与定性排序，不冒充那 1000 条的真实实验结果。

### 2. 再确认：阻断实验把功劳判给前馈层

因果跟踪圈出的是一整层 Transformer，它内部还有前馈与注意力两个模块，功劳要分清。阻断实验的做法是改恢复的路径：恢复某一层处理 s(-1) 的输出之后，把后续的前馈层（或注意力层）冻结在干扰状态，等于把那条后续计算隔离掉，再看因果效应掉多少。

结果不对称得很干净：后续前馈层被阻断，中间层处理 s(-1) 的因果效应几乎消失；末尾层的效应则几乎不受前馈缺失影响。反过来阻断注意力层，各层在 s(-1) 处的效应只有较小下降。两步合起来，ROME 的定位结论落地：知识存储于中间层的全连接前馈层，并且是在处理主体末尾 Token 的那个时刻起作用。上一篇 T-Patcher 把补丁贴在最后一层，靠的是「贴近输出、改动不被后续层稀释」的工程理由；ROME 的编辑位置是实验测出来的中间层，靠的是因果证据。两种选址逻辑完全不同，这是两篇对照读时最值得记住的一点。

### 3. 存储机制假设：三段接力与键值映射

位置定下，机制还要有一套能指导编辑的说法。教材汇总了三方观点：Geva 等人把前馈层看作键值存储体，与定位实验一致；Elhage 等人指出注意力头的作用是搬运与复制信息，每个头可看作独立运算单元，通过查询-键与输出-值两类电路把信息送进残差流；Zhao 等人发现不同层位置互换对性能影响不大，说明多层结构的功能有相似性。

ROME 在此之上的假设是一条三段接力：起始层的注意力先收集主体 s 的信息，汇入主体最后一个 Token 的向量表示；中间层的前馈层拿这个表示去查询，把查到的相关信息融进残差流；末尾的注意力再捕获并整理隐藏状态，生成输出。同时知识被假设以键值映射的形式等价地存储在任何一个中间层的前馈层里。注意教材的措辞分寸：这是基于定位实验与既有研究做出的合理假设，不是被单独证明的定理。本篇照这个分寸写——编辑方法建立在假设之上，假设若被修正，编辑位置的选择也要跟着复核。

### 4. 编辑第一步与第二步：平均出键向量，优化出值向量

编辑位置选定某个中间层前馈层后，剩下三步。第一步定键向量 k*：它就是 s(-1) 在被编辑层里经过激活函数后的输出，应当编码着主体本身。为了不让某一次输入的偶然搭配污染它，ROME 在主体前拼接不同的随机前缀文本、多次运行，再取平均，式 5.15 就是这个平均：k* 等于 N 个前缀样本各自激活向量的均值。我的脚本用四个三维玩具样本复算，平均确实把单个样本的偏移摊薄了——键认的是主体，不是某一条前缀。

第二步定值向量 v*：它是下投影矩阵作用在 k* 之后应该输出的期望值，应当把（r, o）编码成主体的新属性。定法不是查表，是优化：把被编辑层的输出当作可训练变量做梯度下降，损失由两项组成，式 5.16 写成 L(v)=L1(v)+L2(v)。L1 管准确性，式 5.17：同样拼随机前缀，要求目标客体 o 的概率最大化，写出来是 o 的负对数概率在 N 个前缀上的平均；L2 管局部性，式 5.18：在「斑马是」这类只谈主体含义的 prompt 上，让编辑中的模型与原模型的输出分布 KL 散度最小，防止为了改一条肤色事实把「斑马是什么」也一起带偏。脚本复算：P(o) 从 0.10 升到 0.85，L1 从 2.303 降到 0.163；分布几乎不变时 KL 约 0.0008，严重偏移时约 0.8382。两项缺一不可：只有 L1，改对了新题、带歪了主体；只有 L2，什么都不敢改。

这里还有一处与上一篇不同的键值口径，必须分清：T-Patcher 把上投影矩阵的参数向量看作键、下投影矩阵的参数向量看作值；ROME 把下投影矩阵的输入向量看作键、把它的输出向量看作值。前者是仓库货架的编号与存货，后者是一次实际查询的入参和出参。同叫键值存储体，指的不是同一样东西，混读会把两篇的公式全对错位。

### 5. 编辑第三步：插入知识是一个带约束最小二乘，解是秩一的

k* 与 v* 都有了，最后一步是把下投影矩阵 W 改成新矩阵，使它作用在 k* 上恰好得到 v*，同时尽量不破坏它原有的键值映射。教材把原矩阵看作线性键值存储体：旧键集 K 与旧值集 V 满足 W 作用于 K 约等于 V。插入问题于是写成式 5.19 与 5.20：最小化新矩阵作用于旧键集与旧值集的偏差，约束是新矩阵作用于 k* 必须严格等于 v*。

这个带线性等式约束的最小二乘有闭式解，式 5.21：新矩阵等于原矩阵加上一个外积更新，更新等于列向量 Lambda 与行向量（C 的逆作用于 k*）的转置相乘，其中 C 是旧键集的自相关矩阵 K 与其转置的乘积，由维基百科大量文本样本估计、预先算好；Lambda 等于新映射的残差（v* 减原矩阵作用于 k*）除以一个标量分母。因为更新矩阵是一个列向量乘一个行向量，它的秩为一——Rank-One Model Editing 的名字就是这么来的，不需要训练、不需要迭代，一次代数运算直接把新键值对插进去。

我的脚本把这一步完整复算：自选旧键集构造 C 并求逆，按式 5.21 更新后，新矩阵作用于 k* 与 v* 的残差为 0；更新矩阵每一行都是同一个向量的倍数，秩一断言通过。脚本同时如实演示了它的边界：闭式解保证的是约束精确满足加上最小二乘意义下的总体偏差最小，不是每一条旧知识逐条零改动——某个旧键的映射在玩具里照样被扰动。读 ROME 时把「不破坏原有信息」读成逐条不动，是夸大；教材的原话是尽量避免影响，量词别替它升级。

### 6. 成绩、局限与它在全章里的位置

表 5.2 里 ROME 是准确性、泛化性、可迁移性、局部性四项全高，与 MEMIT 并列全表最好，但高效性一栏是不支持批量。教材在节末把局限写明两条：编辑目标局限于知识元组形式，处理复杂事实时可能表现不佳；不支持批量编辑。后续工作 MEMIT 正是冲着第二条去的：在 ROME 基础上做并行批量编辑，同时编辑大量事实，并声称提高效率与规模、增强精度和鲁棒性——那是下一篇的事，本篇不把 MEMIT 的能力记在 ROME 头上。

回看全章的方法谱系，ROME 与 T-Patcher 构成最干净的一组对照：一个往最后一层加一对新键值、原参数冻结、靠训补丁的两组损失守住局部性；一个先做因果实验定位到中间层、再直接改那一层的下投影矩阵、靠约束优化守住旧映射。一个是加法，一个是改法；一个的位置来自工程便利，一个的位置来自因果证据。选哪条路，先问你要改的知识有没有元组形状、要改一条还是一批——答案不同，工具就不同。

## 我的思考/应用

- **改任何存量系统之前，先做一次自己的因果跟踪。** ROME 最值钱的不是秩一公式，是顺序：先干扰、再逐个恢复，用证据把出问题的位置圈出来，然后才动手。我们维护讲稿库存、课程与教会系统时同理：一处事实错了，先查它是从哪一层进来的——源稿、翻译、排版还是分发——定位层错了，改得再精细也只是给错误换了个位置。（成本：动手前多一轮定位实验；收益：不把编辑做在无辜的那一层上；证据 B，因果跟踪与阻断实验的步骤与结论为教材原文，本篇脚本复算其定义与排序）
- **给一条事实定「键」时，用多个上下文平均，别用单次出现。** 式 5.15 拼随机前缀求平均，防的是键被某一次搭配带偏。落到我们自己的知识库与检索：给一个条目定触发词、标签或索引键时，拿它在不同文档、不同问法下的多个样本一起定，别按它第一次出现的上下文一锤定音，单样本的键上线后泛化必然飘。（成本：定键时多收集几个样本；收益：换个问法还能命中同一条纠错；证据 B，式 5.15 的平均构造与泛化意图为教材原文）
- **改一条内容时，验收必须同时有两项：一项看新答案对不对，一项看主体本身有没有被带偏。** L2 用的 prompt 不是无关问题，而是「斑马是」这种直指主体含义的问题——它守的是被改对象本身的其余属性。我们做勘误时照搬：改完一处，除了验改的那句，还要抽查同一对象最核心的几条定义有没有跟着变，这比拿一批完全无关的内容做抽查更能抓到带偏。（成本：每类对象维护几条核心定义作回归样本；收益：带偏在验收环节暴露，不等读者发现；证据 B，式 5.18 的 KL 项与主体含义 prompt 口径为教材原文）
- **「尽量不影响其他内容」必须追问是哪种保证：逐条不动，还是总体最优。** ROME 的闭式解是后者。它照样是好方法，但宣传口径若把它说成前者，验收时就会用错标准。我们评估任何批量修订、自动替换或系统迁移方案时，先把这句问清并写进验收单：保证的类型不同，抽查方法和通过线完全不同。（成本：立项时多问一句并写明；收益：不拿逐条零改动的标准去判一个只承诺总体最优的方案，也不反过来放水；证据 A，式 5.19 的最小二乘目标与约束形式可逐式复查，本篇脚本已复算约束残差与旧键扰动量）

## 视频脚本要点（动画短片用）

1. 开场钩子：上一篇往仓库里加了一个新格子，这一篇不加了——先派侦探进仓库，挨个货架断电再通电，看哪一格一断电，模型就把斑马的肤色记错。查清了，才动手换货。
2. 断电实验动画：一排楼层亮着灯，先整栋断电，答案熄灭；再逐层逐间通电，只恢复一间就记录答案亮回来多少——中间那一层、主体最后一个字的那一间，亮回来的最多。
3. 分功劳动画：同一间房里站着两个人，一个管搬运、一个管存货；把管存货的请出去，刚亮回来的答案又灭了；把管搬运的请出去，答案只是暗了一点——存货的才是管知识的。
4. 平均钥匙动画：同一把钥匙在四个不同的门口各配一次，四把钥匙叠在一起取平均，毛刺被磨平——配出来的钥匙认的是这扇门本身，不是某一次站在门口的人。
5. 结尾钩子：一把钥匙配一个答案，一次代数运算直接换掉一格货——干净利落，可它一次只能换一格。下一篇，MEMIT 登场：同一套手艺，怎么一次换掉一整排货架。

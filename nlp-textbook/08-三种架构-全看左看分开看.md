# NLP 读书笔记（08）：三种架构——全看、只看左边、分开看

> 来源：中文 NLP 教材（浙江大学），《Foundations of LLMs》讲义第二章 2.2 节（大语言模型的基本架构）
> 覆盖：书页码 40–48 · 本篇为 clean-room 重写，代码为自写示例并已运行验证

## 一句话核心观点

Transformer 只有一套积木，但搭法有三种，区别只在一件事——**每个位置能看见谁**：Encoder-only 让每个词看全整句话（双向），天生是"理解"的料；Decoder-only 给每个词戴上眼罩、只许看左边（因果掩码），天生是"生成"的料；Encoder-Decoder 把活拆成两半，一半负责看懂输入、一半负责生成输出（中间靠交叉注意力传话），天生是"转换"的料。**可见性决定任务形态，最后赢下 AIGC 时代的，是训练信号最密、玩法最统一的 Decoder-only。**

## 详细解读

### 1. 同一套积木，三种搭法

先把上一站的结论接上：Transformer 的核心零件是自注意力（Self-Attention）加前馈网络，叠多少层都行。教材 2.2 节做的事，是把市面上所有主流模型按"零件怎么拼"分成三家（教材图 2.3–2.5 把三种结构的流程图并排画了出来，对比非常直观）：

- **Encoder-only（纯编码器）**：只有编码器一摞。流程是"输入编码 → 特征编码 → 任务处理（可选输出头）"：文本先分词、过词嵌入矩阵、加位置编码，再穿过 M 个一模一样的编码块，最后接一个任务头（分类就接分类头，做抽取式问答就接起止位置头）。
- **Encoder-Decoder（编码器-解码器）**：两摞。左边编码器把输入读成一串特征向量；右边解码器一边生成输出、一边通过交叉注意力（Cross-Attention）回头看编码器的结果。流程是"输入编码 → 特征编码"和"输出编码 → 特征解码 → 输出生成（线性层加 Softmax 采样）"两条线并行，中间靠交叉注意力咬合。
- **Decoder-only（纯解码器）**：只有解码器一摞。输入和输出不分家，拼成一条序列：前半段是条件（提示词），后半段是要生成的内容，一个词一个词往后续。它没有独立的"特征编码"阶段，理解和生成在同一摞模块里完成。

三家的零件几乎一样，真正的分水岭不在零件，在注意力掩码——谁能看见谁。

### 2. 注意力掩码：三种"视野"，三种命运

教材 2.2.2 节用注意力矩阵（Attention Matrix）把这件事讲透了。把"位置 i 能不能看位置 j"画成一张表，三家的表长得完全不同（我的验证代码把这三张表打了出来，见下节）：

- **Encoder-only：满矩阵。** 每个位置能看全部位置，包括右边的。处理"银行"这个词时，它同时知道左边是"我去了"、右边是"存钱"还是"河边"——词义靠全上下文定，所以它做理解类任务（教材称 NLU，Natural Language Understanding）最强。
- **Decoder-only：下三角矩阵。** 第 i 个位置只能看 1 到 i，右边一律挡住（因果掩码，Causal Mask）。为什么必须挡？因为它的训练方式是"预测下一个词"——要是能偷看右边，等于考试时翻答案，学不到真本事。代价是它理解一个词时只有左半边信息；回报是训练和生成的方式完全一致：生成就是把"预测下一个词"重复到底。
- **Encoder-Decoder：自家下三角 + 交叉满矩阵。** 解码器看自己已生成的内容时是下三角（同样不能偷看未来），但通过交叉注意力看编码器的输出时是满矩阵——输出端的每个位置，都能回看输入的全部内容。翻译时生成第 3 个英文词，可以同时盯着整句中文，这正是"转换"任务需要的视野。

一句话总结这一节：**掩码即命运。** 满矩阵适合"先把整段读完再答题"，下三角适合"边写边想下一个字"，分开的两张表适合"看着原文写译文"。

### 3. 预测目标：三种架构在"猜"不同的东西

视野不同，训练时猜的东西也不同（教材在图 2.6 里按 Token 预测关系做了对比）：

- **Encoder-only 猜"被遮住的词"。** 代表玩法是掩码语言建模（MLM）：随机遮住输入里约 15% 的词，让模型用左右两边的上下文把它们猜出来。它猜的是序列内部的 Token（x_i，条件是整段 x 去掉被遮部分）。信号密度低——一句话只有被遮的那几个位置产生训练信号——但每个信号都用上了双向信息，学出来的表示质量高。
- **Encoder-Decoder 猜"输出序列的下一个词"。** 预测的 Token（y_i）以两样东西为条件：整段输入 x（通过交叉注意力）和已经生成的输出前缀 y_1 到 y_{i-1}（通过因果自注意力）。输入和输出分工明确，天然对位机器翻译、摘要、改写这类"输入一段、输出另一段"的活。
- **Decoder-only 猜"序列的下一个词"，没有例外。** 输入和输出是同一条序列，预测第 i 个 Token 时条件就是它左边的全部 Token。它不需要区分"哪段是输入、哪段是输出"——分类、问答、翻译、对话，全都可以改写成"给定上文、续写下文"。这是三家里最笨、也最统一的猜法。

把三家的训练信号密度算一笔账（验证代码里有具体数字）：20 个 Token 的句子，MLM 只有约 3 个位置算损失；Decoder-only 有 19 个位置算损失。**近 6 倍的信号密度差距**，在小规模时看不出来，到上一篇讲的缩放定律那个量级上，就是决定胜负的因素之一——同样的算力，Decoder-only 从每个句子里榨出的学习量最多。

### 4. 演化史：为什么最后是 Decoder-only 赢了

教材 2.2.3 节排了一条简史，读起来像一场三家争霸：

- **2018 年，双雄并起。** BERT（Encoder-only）和 GPT-1（Decoder-only）同年出现，路线之争一开始是平手：理解任务 BERT 占优，生成任务 GPT 占优，Encoder-Decoder 则在翻译等序列到序列（Sequence-to-Sequence）任务里站稳。
- **2019–2020 年，三分天下。** T5、BART 把 Encoder-Decoder 推到高点，试图用"一切任务都改写成文本到文本"来统一江湖；GPT-3（2020）则证明 Decoder-only 靠规模加上下文学习（In-Context Learning）能把分类、问答这些本属理解的任务也用"续写"的方式办了。
- **2021 年之后，Decoder-only 事实上胜出。** 教材给的判断很克制，但图景很清楚：到了 AIGC 时代，主流大模型（GPT-3、GPT-4 一系）清一色 Decoder-only。原因把前面三节串起来就通了：第一，信号密度最高，缩放最划算（接上一篇的 Chinchilla 账）；第二，玩法统一——一个"预测下一个词"的目标吃下所有任务，不用为每个任务换结构、换输出头；第三，推理时天然适配自回归生成和 KV 缓存这类加速手段，工程上越滚越顺。

但教材没有把另两家判死刑，这个态度是对的：Encoder-only 在只要理解、不要生成的场景（检索向量、分类、打标）里仍然是性价比最优解——它一次前向就能出整句的表示，不用逐词生成；Encoder-Decoder 在输入输出边界清晰、输出长度可控的转换任务（翻译、摘要）里也依然能打。**选架构的正确姿势不是站队，是看你的活是"理解、生成、还是转换"。**

### 5. 一个容易忽略的细节：Teacher Forcing 只出现在哪一家

教材在讲 Encoder-Decoder 的图（2.4）里专门标了 Teacher Forcing：训练解码器时，不喂它自己上一步生成的词，直接喂标准答案的上一个词（Ground Truth），让它每一步都站在正确答案的肩膀上学。这也是 Decoder-only 训练时的做法（整条序列都是现成的，左边的词全是真的）。它带来的老问题在第 03 篇 RNN 时就提过——曝光偏差：训练时步步有正确答案兜底，真生成时一步错、步步歪。理解这一点，就理解了为什么解码策略（第 05 篇）和后来的对齐训练（后面的章节）必须存在：架构给了生成能力，但"生成得稳"要靠别的东西补。

## 代码验证（已运行）

自写脚本 `08-three-architectures-verify.py`（numpy，手写，无教材代码），做了四件事：打印三种架构的注意力可见性矩阵；用同一组注意力分数演示掩码如何把"未来位置"的权重严格压成 0；对比三种架构在一条 20 Token 句子上的训练信号数量。

```python
import numpy as np

n = 5  # 序列长度示意
# 1) Encoder-only: 双向自注意力，谁都能看全序列
enc_mask = np.ones((n, n))
# 2) Decoder-only: 因果掩码，只能看自己和左边
dec_mask = np.tril(np.ones((n, n)))
# 3) Encoder-Decoder 交叉注意力: 解码端每个位置看全部输入（输入长 m=4）
cross_mask = np.ones((n, 4))

# 同一组 QK 分数，套不同掩码后做 softmax
scores = np.array([[2.0, 1.0, 0.0, -1.0, -2.0]] * n, dtype=float)
def masked_softmax(s, mask):
    s2 = np.where(mask > 0, s, -1e9)
    e = np.exp(s2 - s2.max(axis=1, keepdims=True))
    return e / e.sum(axis=1, keepdims=True)
```

**实际运行输出**（节选，已验证）：

```
Encoder-only 自注意力: 可见对数 25/25 —— 每个位置平均能看 5.0 个位置
Decoder-only 因果自注意力: 可见对数 15/25 —— 第 i 个位置只能看 i+1 个（含自己）
Encoder-Decoder 交叉注意力: 可见对数 20/20 —— 输出端每个位置都能回看全部输入

同一行分数 [2,1,0,-1,-2]，第 3 个位置的注意力权重:
 Encoder-only : [0.636 0.234 0.086 0.032 0.012] -> 左右都能分到权重
 Decoder-only : [0.665 0.245 0.090 0.000 0.000] -> 右边两个位置严格为 0，没偷看未来

训练信号对比（20 个 token 的句子）:
 Encoder-only / MLM: 约 3 个位置算 loss
 Decoder-only / 自回归: 19 个位置算 loss
 Encoder-Decoder / seq2seq: 输出端 12 个位置算 loss
```

几点说明：掩码用 -1e9 填充后再做 softmax，是实际框架里的标准做法（等效于权重为 0，不是近似技巧）；MLM 的 15% 是 BERT 的经典设定，教材后续 2.3 节讲 BERT 时会展开；信号密度的对比只说明"每个样本产出的梯度信号多少"，不直接等于效果——Encoder-only 信号虽少，但每个信号带双向信息，这正是它在理解任务上仍不可替代的原因。

## 我的思考/应用

- **给我的 AI 项目选型，这篇就是决策表。** 雨刷 WhatsApp 客服和 Wiper-Service-Agent：核心是"读懂客户问题再生成回复"，是生成活，用 Decoder-only 的现成大模型走 API 就对了，没必要自己训。但 Emotion-Guard、Bloom-Counter 这类要对画面和文本做判断、打标的活，本质是理解和分类——如果哪天要自建小模型，Encoder-only 出向量加个分类头，是最省算力的路线，别拿生成式大模型去干打标的活，又慢又贵。选架构先问一句：我的活是理解、生成，还是转换？（成本：0，只是选型思路；收益：避免用最贵的架构干最便宜的活；证据 B，教材结论加工程共识）
- **"信号密度"这个账，可以搬到内容生产上。** Decoder-only 赢在每个样本榨出的学习信号最多。同理看我的拆书流水线：一篇笔记如果只产出"一篇文章"，信号密度是 1；现在的做法是每篇同时产出文章、视频脚本要点、GitHub 提交记录（EB-1A 证据链）和我自己的应用清单，一份输入四份产出——这就是内容版的"每个位置都算 loss"。以后每条生产线都该问：这份素材，我榨干了吗？（证据 C，类比迁移）
- **交叉注意力给客服机器人的启发。** Encoder-Decoder 生成每个词时都回看全部输入，而不是只看自己刚说的话。客服翻车最常见的样子恰好相反：聊到第五轮就忘了客户第一句说的车型和年份。对策现成：把关键事实（车型、年份、故障现象）结构化存下来，每轮回复前强制"回看"一遍——这就是人肉版交叉注意力。我的 WABA 机器人下一版就把这个写进系统提示的结构里。（证据 C，设计启发）
- **Teacher Forcing 的曝光偏差，放到带人上也成立。** 训练时步步有人喂正确答案，真上场时一步错步步歪——新人培训同理：培训期全程有人兜底，第一次独立值班就容易连环出错。解法也和模型训练的演进一样：从全兜底慢慢过渡到"让他先自己生成、错了再纠"，给独立生成的比例留一个逐步升高的日程表。（证据 C，类比；模型侧的 scheduled sampling 是 B 级文献结论）
- **别站队，要对位。** 这几年社区吵"哪种架构最强"吵得很凶，这篇给我的冷静剂是：BERT 系在检索和分类里活得好好的，T5 系在翻译里也没退场。技术选型的成熟标志，是从"我喜欢哪个"变成"我的任务形态匹配哪个"。这条对我选工具、选平台同样适用——飞轮里每个平台都是某种"架构"，对位比站队重要。

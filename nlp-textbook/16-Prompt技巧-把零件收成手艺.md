# NLP 读书笔记（16）：Prompt 技巧——把零件收成手艺

> 来源：中文 NLP 教材（浙江大学），《Foundations of LLMs》讲义第三章 3.4 节
> 覆盖：书页码 122–137（3.4 Prompt 技巧：规范编写、合理归纳提问、适时使用思维链、善用心理暗示）· 本篇为 clean-room 重写，例题与代码均为自编并已运行验证

## 一句话核心观点

前三节是零件，这一节是手艺：3.1 给了 Prompt 的四个基本元素，3.2 给了上下文学习，3.3 给了思维链，**3.4 把它们收成四组能直接照着做的技巧——规范 Prompt 编写、合理归纳提问、适时使用思维链、善用心理暗示。** 贯穿四组技巧的是同一个判断：模型答得好不好，很多时候不取决于模型，而取决于提问的人有没有把任务说明说清、上下文给对、问题拆好、链用对场合，再用对角色和情景把模型脑子里本来就有的知识"喊"到正确的位置上。技巧的共同点依然是那句老话：不改一个参数，全靠输入端的手艺。

## 详细解读

### 1. 这一节的位置：从"有什么"到"怎么用"

第 14 篇讲上下文学习时说过，选例有纪律；第 15 篇讲思维链时说过，链有适用边界。3.4 做的事是把这些散落的纪律汇总成一份操作手册，分量最重的是第一组"规范编写"——它其实是把 3.1 的四要素逐条落成验收标准。后三组则依次回答三个进阶问题：问题本身该怎么问（归纳提问）、链该什么时候用（适时 CoT）、怎么让模型进入状态（心理暗示）。读这一节要带着一个意识：每条技巧背后都有一个对照实验式的例子，正反各一，差别只在 Prompt 的写法，不在模型。

### 2. 规范编写之一：任务说明要明确

经典 Prompt 由四部分组成——任务说明、上下文、问题、输出格式（3.1 已立）。3.4.1 给出的四条规范里，前三条分别落在这四部分中的任务说明、上下文、输出格式上，第四条"排版清晰"管的则是四部分整体的切分与布局。第一条规范落在任务说明上：它必须明确。教材给的对照很直白：只说"分类下面的句子"，模型连按什么维度分都不知道，输出自然跑偏；把任务类型和类别名一并写明（判断情感、类别是积极还是消极），输出立刻回到正轨。落成可操作的检查项有四条：用明确的动词（判断、分类、生成这类，不要用"处理""操作"这种什么都能套的词）；用具体的名词把输出目标钉死（类别名、字段名直接写出来）；句子简洁直接，不绕弯；长 Prompt 里把任务说明放在开头和结尾各出现一次，因为模型对首尾位置的信息更敏感（呼应第 14 篇讲的示例位置效应，同一条注意力规律）。我的验证脚本把这四条做成了体检函数：模糊版任务说明一次命中四个问题，明确版零问题——规范这东西，是可以写成检查清单的。

### 3. 规范编写之二：上下文丰富且清晰

第二条规范管上下文，两个词：丰富、清晰，而且两者不能互相打架。丰富指与问题直接相关的信息给够——背景、示例、约束，该有的都有；清晰指只给相关的，无关细节一律剔除。教材的反例很典型：只给一个示例，却把大量与判定无关的情节塞进这一个示例里，模型被无关细节带偏，不但答案翻转，输出格式也跟着失控（该给标签的地方给了一大段解释）。这和第 14 篇的选例纪律是同一件事的两面：14 篇讲"选哪些例"，这里讲"例本身写成什么样"——示例不是越长越有诚意，示例里的每一句无关的话，都是在替模型埋分心的种子。一句话收束：丰富是"相关的给够"，不是"字数给够"。

### 4. 规范编写之三、四：输出格式要规范，排版要清晰

第三条管输出格式：明确指定结构化格式（JSON、XML、HTML、Markdown、CSV 各有适用场景），并给出一个带字段名的样例。理由是工程性的：结构化输出能被程序直接解析、校验、入库；自由文本则要靠字符串硬抠，模型换个说法解析就失效。我的验证脚本演示了这条差距：JSON 一行代码取到字段，自由文本只能靠正则猜位置；顺带还验证了另一面——坏 JSON 会当场报错，错误是显形的，不会静默流进下游。第四条管排版：用一致的分隔符（教材用的是 # 与 ### 一类标记）把四部分切开，配上空白、缩进和标题。反例同样直观：把分隔符全去掉、四部分糊成一团，模型分不清哪段是示例、哪段是问题，干脆把示例也当成待答内容一起输出，格式彻底崩坏。排版不是美观问题，是给模型的"分段信号"——模型没有眼睛，它靠这些标记理解结构。

### 5. 合理归纳提问之一：复杂问题拆解

第二组技巧从"写"转向"问"。第一招是拆解：复杂问题不要一口问出，先拆成几个能独立回答的子问题，逐一问清，再用一句归纳性的提问把子答案合成最终答案。教材把两步分得很清：分步引导管"拆开逐个答透"，归纳总结管"合起来算总账"，并借用了算法里的说法——分而治之。它演示的热量类问题正是这个形状：直接问"一天要吃多少份"，模型只能凭空估；先分别问清单日总需求和单份含量两个子问题，最后一除，总账自己就出来了。我的验证脚本用一道仓库保本量的问题复刻了这个骨架：日固定开支 400 元、单箱毛利 8 元，归纳一步得到每天 50 箱保本。拆解的真正价值不在算术，而在把"模型需要哪些中间量"这件事从模型的猜测，变成提问者的设计——中间量先钉死，最终答案就没有腾挪造假的空间。

### 6. 合理归纳提问之二：三种追问

第二招是追问：第一轮答案只是起点，用后续提问把答案往深、往宽、往对的方向推。教材按目的分三类。**深入追问**：顺着一个点往下钻，要更细的条件和边界（比如从"能不能吃"追到"去掉某个成分之后能不能吃"，答案随之细化到份量和搭配）。**扩展追问**：从一个点往旁边铺开，要更多的相关信息和选项，先把全景看全再做判断。**反馈追问**：答案与事实或预期不符时，把新情况（比如已经出现不良反应）摆出来，要求模型更正——教材的例子里，模型收到反馈后明确收回先前的说法，给出正确的处置建议。三类追问合起来是一套对话节奏：先拆（招一），再沿深度、广度、正确性三个方向逐轮收紧。也要看到反馈追问的一体两面：它能纠错，说明模型的立场会被对话推着走；如果用户反馈本身是错的，同样的机制也可能把对的答案"纠"错——这一点教材没有展开，我在思考部分单独钉住。

### 7. 适时使用 CoT 之一：何时用，看三件事

第三组技巧是给第 15 篇的思维链补一张使用说明书。先说"何时用"，教材列了三个考量因素。**任务类别**：算术、常识推理、符号推理这类多步任务是链的主场；情感分类、简单问答这类一步任务，标准提示已经够用，上链只添乱。**模型规模**：链是涌现能力的又一例——教材的对照里，同一道多步题，千亿级模型的链条条对得上、答案正确，十亿级模型的链看着像模像样、中途一步滑掉、答案反而比直答更离谱；规模不够，链不是拐杖，是绊索。**模型能力（是否已内化）**：没有做过推理类指令微调的基础模型，需要显式提示把链"喊"出来；而已经做过这类微调的对话模型，推理步骤已经内化，不给触发词也会自发分步，有时硬加显式 CoT 反而表现更差。我的验证脚本把这三因素写成了一个决策函数，四种组合各给一条明确建议——选型表这种东西，就应该做到能查表执行、不靠临场感觉。

### 8. 适时使用 CoT 之二：灵活用，调详略、选形式

再说"如何用"，两个调节钮。**详细程度**：链写多细，由示例说了算——示例只给算式和结果，模型就只给算式和结果；示例把每步的道理都写全，模型就照着写全。用户只要答案时给简略示例，用户要看过程（教学、审计、排障）时给完整示例，详略是需求问题，不是模型问题。**形式选择**：按场景挑第 15 篇的流派——纯逻辑推理、不需要领域知识的，用零样本或自动构造示例的 CoT；要高可靠的（教材举的是代码生成，多版本互校），用自一致性多路采样取共识；要发散探索的（比如故事创作的多条情节线），用思维树、思维图去探路再选优。一句话：链不是一根，是一套长短不一的尺子，先量任务再选尺。

### 9. 善用心理暗示：角色扮演与情景代入

第四组技巧最"玄"，教材开篇借了硅谷那句"Fake it till you make it"定调：积极的心理暗示对人有用，对模型同样有用，因为模型的知识本来就按人物、场景、文体组织着，暗示的作用，是用角色和场景改变模型续写的条件：给定"谁在说、在什么场合说"，模型会顺着预训练里与这类人物、这类场景相伴出现的表达和知识往下写，相关的那部分能力就被调了出来。两条落地路径。**角色扮演**：给模型设定一个与任务对口的角色，且角色要写全——身份、职责、知识、技能都交代清楚，还要挑对任务明显占优的角色并把优势点明。教材的对照里，同样问饮食搭配问题，不设角色时模型只给一句笼统的否定，设上专业营养顾问的角色后，答案立刻有了原则、有份量控制、有搭配方案，专业度完全不是一个档次。**情景代入**：把时代、地点、氛围等背景嵌进提问，模型会连带调用那个情景下的文化与常识——教材把提问放回九十年代的街头场景后，答案里自然长出了集卡、交换这类属于那个年代的细节，从"答对"变成了"答得有共鸣"。边界也要说清：暗示调动的是知识的调用倾向和文风，不新增事实；角色演得再像专家，输出的专业结论该核还是要核。

### 10. 这一节与前后章的咬合

往回看：四组技巧分别踩在前三节的地基上——规范编写的前三条是 3.1 四要素中任务说明、上下文、输出格式三部分的验收标准，第四条排版管整体布局；上下文规范是 3.2 选例纪律的写作版，何时用 CoT 是 3.3 的选型版，角色扮演则和 3.2 的"锚定"解释一脉相承：角色和情景本质上都是更强的锚。往后看：3.5 的四类应用（Agent、数据合成、Text-to-SQL、GPTs）全是本节技巧的组合实战——比如 Text-to-SQL 里成熟的提示框架，拆开看正是清晰排版、清晰上下文、角色校准、自一致性输出这四招的拼装。学完 3.4 再看 3.5，会有一种"招式都见过、只是编排不同"的感觉，这正是教材把技巧节放在应用节前面的用意。

## 代码验证（已运行）

自写脚本 `16-prompt-tips-verify.py`（仅标准库，固定数据，可复现），做了四件事：四件套 Prompt 的拼装与体检（明确版与模糊版对照）；JSON 结构化输出与自由文本在可解析性上的差距（含坏 JSON 当场报错的演示）；一道仓库保本量问题的分步拆解与归纳总结；按教材三因素（任务类别、模型规模、是否已内化推理）实现的 CoT 适用性决策函数。

```python
def cot_advice(task_kind, params_b, reasoning_tuned):
    if task_kind == "simple":
        return "不用 CoT：一步任务标准提示已够，硬上链只烧 token"
    if reasoning_tuned:
        return "可不用显式 CoT：推理已内化进模型，先直答、不行再加链"
    if params_b < 20:
        return "慎用 CoT：小模型链容易不连贯，可能还不如直答，先小样实测"
    return "用 CoT：多步推理 + 大模型 + 未内化推理，正是链的主场"
```

## 我的思考/应用

- **把四件套体检固化成所有生产线的提示模板出厂检查。** 凡是要反复用的提示（拆书、审稿、战报、Text-to-SQL 类查询），入库前过一遍清单：动词明确吗、类别词写死吗、上下文有没有无关句、输出格式带字段样例吗、分隔符统一吗。过不了清单的提示不许上线，和代码过不了测试不许合并是一个道理。（成本：每个模板多几分钟检查；收益：省掉因提示含糊导致的整批返工；证据 B，教材四条规范与对照例子的直接推论）
- **凡是给程序吃的输出，一律结构化，不留自由文本口子。** 本篇的 JSON 对照和后面 Text-to-SQL 的一致输出要求是同一条工程纪律：模型输出要进下游，就必须可解析、可校验、出错显形。我们各条线凡是"生成完还要再处理"的环节，都按这个口径收口。（成本：模板设计时多写一截格式说明与样例；收益：解析失败从"静默用错"变成"当场报错"，事故形态完全不同；证据 B，教材输出格式规范的直接推论，脚本已实测演示）
- **复杂问题先由我拆，再逐个问，最后归纳——拆解是提问者的活，不是模型的运气。** 日常指挥模型做研判、核账、排障时，先列子问题清单再开问，中间量逐个钉死；这和给 Agent 派活时先拆任务是同一套动作。（成本：提问前多花几分钟列子问题；收益：最终答案的每个中间量都可单独复核，错了能定位到步；证据 B，教材拆解两步法的直接应用）
- **CoT 按选型表用，不凭手感。** 一步任务不用链，多步推理先看模型规模与是否已内化推理再决定显式加链还是直答，详略由示例控制、形式按可靠性要求选。（成本：0，查表纪律；收益：省下简单任务上白烧的推理 token，也避免小模型上链反而更错；证据 B，教材三因素与详略/形式两节的直接推论，门槛数字为我的工程取舍）
- **反馈追问是双刃剑：纠错时给事实，不给立场压力。** 教材的例子里模型收到反馈立刻改口，这是好事；但同一机制下，用户拿错误的"事实"去压模型，也可能把本来对的答案压翻。我的用法：反馈时只摆可核查的新情况（数据、现象、出处），请模型据此重判，而不是说"你错了，按我说的改"。（成本：0，反馈写法的纪律；收益：既用上纠错通道，又不把迎合通道一起打开；证据 C，我的使用经验判断，教材示例的反向提醒）
- **角色扮演天天在用，但要防"入戏太深"。** 给审稿、校对、顾问类任务设对口角色，确实能把专业知识喊到前台；但角色给的是视角和文风，不是资质——顶着专家角色说出的话，核验标准一条都不能降，越是说得像专家，越要核。（成本：0，纪律；收益：拿到角色扮演的质量红利，又不付"因为像专家就信了"的学费；证据 C，我的工程经验判断，与教材角色扮演机制不冲突）

## 视频脚本要点（动画短片用）

1. 开场钩子："同一个模型，同一道题，只改提问的写法，一个答得驴唇不对马嘴，一个分毫不差——差的不是智商，是手艺。这一篇，把提问的手艺收成四组技巧。"
2. 四件套体检动画：一张提问单被摊在桌上，四个格子依次亮起——任务说明、上下文、问题、输出格式；镜头切到另一张单子，格子空了两个、动词写着"处理一下"，整张单子被打上红叉——"规范不是讲究，是可以逐项打勾的检查清单。"
3. 糊成一团动画：一张排版整齐的提问单被揉掉所有分隔标记，四段文字流成一滩，模型伸出手在滩里乱抓，把示例当成问题一起端了出来——"模型没有眼睛，它靠分隔符认结构。标记一没，结构就没了。"
4. 拆问题动画：一个大问号被锯成三块小问号，每块被逐个答完、贴上数字标签，最后三块咔哒一声拼回大问号，答案自己浮出来——"复杂问题不靠一口吞：先拆开逐个答透，再合起来算总账。"

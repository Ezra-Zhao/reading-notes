# NLP 读书笔记（21）：低秩适配——给权重外挂两个瘦矩阵

> 来源：中文 NLP 教材（浙江大学），《Foundations of LLMs》讲义第四章 4.4 节
> 覆盖：书页码 167–173（4.4 低秩适配方法：LoRA 的低秩假设与式 4.9、参数与显存账、ReLoRA 合并-重初始化式 4.10、AdaLoRA 的 SVD 式参数化式 4.11–4.12、DoRA 幅度-方向分解式 4.13–4.14、LoRAHub 任务泛化组合式 4.15）· 本篇为 clean-room 重写，例题与代码均为自编并已运行验证

## 一句话核心观点

**低秩适配（LoRA）赌的是一个假设：把预训练模型适配到新任务时，权重真正需要改动的那一部分，本质上是低秩的——一张几千万参数的大矩阵要学的新东西，可以被压缩进两个瘦矩阵的乘积里。** 于是它冻结原权重 W0，只训增量 DeltaW 的两个因子 B 与 A：参数从四千五百万降到六万，梯度与优化器状态跟着瘦身；训完把增量直接加回原权重，模型变回一张普通矩阵，推理不多算一步。它同时拿下了选择派的推理零增负与附加派的底座干净，还把可训量压到了新低——这就是它后来居上、成为 PEFT 默认选项的原因。

## 详细解读

### 1. 这一节的位置：第三家的答案是「增量本身是低秩的」

前两家已经把账算过两遍。附加派（第 19 篇）把新参数挂在模型外面，推理时每一步都要为外挂多付一点；选择派（第 20 篇）只在原参数里挑一小撮训，推理零增负，但挑参的手艺与上限都受原参数本身限制。低秩派换了个提问方式：不问「训哪些参数」，问「权重的改动量长什么样」。微调要学的从来不是一整张新矩阵，而是原矩阵的一个增量 DeltaW。它的理论靠山是教材开篇点名的低维固有维度假设：过参数化模型真正起作用的固有维度其实很低，存在与全参数更新媲美的低维更新。落到矩阵上就是 LoRA 的核心假设：增量虽然形状与原矩阵一样大，它的秩却很低——任务适配真正改变的方向只有少数几个，其余方向上模型原来的表示已经够用。假设成立，增量就可以被两个瘦矩阵的乘积装下，训练的对象从整张增量缩成两个因子。

### 2. LoRA 的机制：一张大矩阵，拆成两个瘦矩阵相乘

设某层预训练权重是 W0，形状 d×k，冻结不动。LoRA 不直接学与它同形的 DeltaW，而是令 DeltaW = B×A，其中 B 是 d×r、A 是 r×k，r 远小于 d 与 k 中的较小者；最终权重 W = W0 + α·B·A（教材式 4.9），α 是缩放因子，用来控制 LoRA 权重的大小。训练时梯度只流进 A 与 B，W0 全程不更新。前向计算有两种等价写法：旁路写法让输入先过原矩阵、再过 A 压到 r 维、过 B 升回来，两路相加；合并写法在训练结束后把 α·B·A 一次性加回 W0，得到一张普通权重矩阵，此后推理与原模型没有任何区别。我的脚本把等价性验到了数值误差量级：两种写法的前向输出最大差 8.88e-16。还有一个初始状态的细节决定了这套办法的安全性：按教材口径，B 用随机高斯分布初始化、A 初始化为零，于是训练起点的 DeltaW 严格为零——脚本验得最大绝对值 0.0——微调从原模型本身出发，不会先把底座打乱再慢慢学回来。挂载位置也有据可查：Transformer 的密集层主要是注意力投影层与前馈网络投影层两类，原始研究把 LoRA 用在注意力层的权重矩阵上，后续工作表明再用到前馈层可以进一步提高性能。最后记一个形态性质：训完的 LoRA 参数可以与模型参数分离，封装成可插拔的插件供多人共享复用——第 8 节的任务泛化就建在这条性质上。

### 3. 参数账：四千五百万对六万

账要算在教材给的锚点上。LLaMA2-7B 的一个前馈矩阵是 11008×4096，一张矩阵就是 45,088,768 个参数；给它挂 r=4 的 LoRA，可训参数是 11008×4＋4×4096＝60,416 个，只有全量的 0.134%，省了约 746 倍——我的脚本逐项复算，与教材口径互证。一般规律是可训量 r×(d＋k) 对全量 d×k：矩阵越大、r 相对越小，省得越狠；脚本另算了两档对照，4096×4096 的矩阵在 r=8 时 LoRA 占 0.39%、r=16 时占 0.78%。秩在这里就是旋钮本身：r 定得越大，增量能表达的方向越多、越接近全量微调的天花板，账也越厚；r 定得太小，任务要学的东西装不下。这个旋钮没有公式可套，只能按任务试——但试错成本被参数账压得很低，这正是 LoRA 敢让人随便试的底气。

### 4. 显存账：省的不只是参数，是训练的整套行李

训练显存从来不止权重本身。教材把这笔账拆成四份：权重显存、激活显存（随批大小与序列长度涨）、梯度显存（只针对可训参数计算）、优化器显存——像 Adam 这类优化器要为每个可训参数额外存一阶与二阶两份动量。全量微调时，四份账全按整模型规模付；LoRA 把可训量压到千分之一量级，省的主要就是后两份。教材引了一组实测对比（LLaMA2-7B、批大小为 1、单张 RTX 4090 24GB）：全量微调约需 60GB 显存，超出一张 4090 的容量；LoRA 约需 23GB，单卡可跑。拆开看，优化器显存约省 25GB、梯度显存约省 14GB；LoRA 新引入的增量参数让激活与权重显存合计多出约 2GB，相对总节省可忽略。附带一笔：可训参数少了，反向传播的计算量跟着降，教材口径下 LoRA 的训练速度约为全量微调的 1.9 倍。这组数字的意义不在精确，而在门槛的性质变了：大模型微调从「必须有多卡服务器」变成「一张消费级显卡可以试」。我的合成任务演示给的是同一件事的机制版：真实增量秩为 3 的任务上，r=4 的 LoRA 用全量 14.6% 的可训参数，把损失降到了与全量微调同等量级——注意这只证明「增量低秩时 LoRA 装得下」，不证明真实任务的增量一定低秩，那是假设，不是定理。

### 5. 低秩假设的边界：秩不够时怎么办

LoRA 的一切红利都押在「增量低秩」上，反过来的问题必须问：任务若需要的是高秩改动呢？教材引的 Biderman 等人实验给了这条边界一个量级：全量微调的有效秩显著高于 LoRA 的秩，差距约在 10 到 100 倍；同时，增大 LoRA 的秩确实能缩小与全量微调的性能差距。教材把变体的第一类改进就定为「打破低秩瓶颈」，代表是 ReLoRA：它承认单个低秩增量装不下，就分段装——训练中周期性地把 α·B·A 合并进权重（教材式 4.10 写的是第 i 轮的合并更新），合并后把 LoRA 模块与优化器状态一并重置：B 用 Kaiming 一类初始化重新生成、A 置零，优化器状态再用幅度剪枝做部分重置，防止重置后性能发散。每轮的可训量仍然只有低秩那一份、总参数量不变，但多轮合并后的总增量秩是各轮累积，可以远超单个 r。我的脚本演示了这个机制：单轮秩上限 4，合并 4 轮后总增量的数值秩达到 16。代价是训练流程变长、每轮都要做合并与重置，它换的是「用时间堆秩」——教材对它的定性是能训出接近全秩训练的模型；当任务确实需要更高秩的改动、又付不起全量微调时，这是一条有明确代价的出路。

### 6. 变体一：AdaLoRA——让秩自己找地方花

固定给每块矩阵同样的 r，是 LoRA 的粗放之处：教材把变体的第二类定为「动态秩分配」，理由有两条——秩并非越高越好，冗余的秩会同时拖累性能与效率；而且不同层的权重重要性不同，本就该分到不同的秩。代表方法 AdaLoRA 把增量改写成奇异值分解的样子：DeltaW = P·Λ·Q（教材式 4.11），P 与 Q 是近正交的因子矩阵，Λ 是对角的奇异值。写法一换，秩就从「预先定死的形状」变成「奇异值里留几个」：它按梯度与权重乘积的移动平均给每个奇异值算重要性得分，迭代剪掉不重要的奇异值——剪掉一处，就等于把那一档秩预算让给更需要的地方。为了让 P、Q 保持近似正交（这样奇异值的含义才成立），它加了一项正交正则 R＝‖PᵀP－I‖²_F＋‖QQᵀ－I‖²_F（教材式 4.12）。我的脚本验了两件事：这种参数化下增量的数值秩仍被 r 卡住；正交正则在 P、Q 真正正交时约为 0（实测 8.14e-31）、随机矩阵时为正值大数——正则项确实只惩罚「不正交」这一件事。AdaLoRA 的账是：省的是秩预算，贵的是训练机制变复杂、重要性统计与剪枝调度都要多操心。

### 7. 变体二：DoRA——先把权重拆成幅度与方向

教材变体的第三类叫「训练过程优化」，针对的是 LoRA 的三个训练侧毛病：收敛比全量微调慢、对超参数敏感、容易过拟合。代表方法 DoRA 的思路是约束梯度更新、把注意力放在权重的方向变化上：先把原权重按列分解为幅度与方向两个组件，W0 = m·(V／‖V‖_c)（教材式 4.13），m 是 1×k 的幅度向量、记每一列的长度，V 是方向矩阵、每一列归一化到单位长度。然后只对方向组件施加 LoRA（幅度单独处理），新权重等于 m 乘上加了 LoRA 增量后再归一化的方向（教材式 4.14），以此增强训练稳定性。我的脚本先验了分解本身：用列范数造出的 m 与单位方向重构原矩阵，最大差 1.11e-16，逐位一致；方向矩阵每列范数全为 1。分解无损， DoRA 多付的只是一组幅度参数与归一化计算，换来的是「大小归大小、方向归方向」的分工，据其思路更贴近全量微调改权重的实际方式。它与 AdaLoRA 放在一起看很有意思：一个在改「秩往哪分配」，一个在改「增量学什么」，都未动 LoRA 的骨架——骨架稳、变体全长在外围，本身就是这套方法生命力的证据。

### 8. 任务泛化：LoRAHub——训好的 LoRA 能不能拼起来用

LoRA 把每个任务的适配压成一份几十万参数的小文件后，一个新问题自然浮现：攒了一柜子 LoRA，来了个新任务，能不能不从头训、把现成的拼一拼就用？这与第 19 篇 AdapterFusion 问的是同一个问题，LoRAHub 给的是低秩版答案，它建立在第 2 节说的可插拔性上，分两个阶段。组合阶段：它设有一个 LoRA 插件仓库，把已学好的若干模块按一组系数 w_i 逐元素线性加权，组合成单一模块（教材式 4.15；组合的是各模块的分解因子两侧，不是一个个增量本身）。适应阶段：给定新任务的少量示例，用无梯度的 Shiwa 方法自适应地学这组组合系数，组合与适应迭代 k 次，直到找到最优权重组合。我的脚本把组合公式的暗坑验了出来：组合增量展开后除了各模块增量的加权项，还多出 w1·w2·(B1A2＋B2A1) 这类交叉项，实测组合增量与「增量的朴素加权和」最大差达 2.34——也就是说，LoRAHub 的组合不是把几个适配效果简单平均，交叉项让模块之间产生了新的配合，组合系数必须专门学、不能凭感觉配；而免梯度学习意味着学系数只需少量样本反复评估，不必为几个系数再跑一轮反向传播。这条线的意义在生态：当 LoRA 文件多到成仓库，适配新任务的成本就从「训一份新的」降成「挑几份旧的、学一组系数」，PEFT 的模块化红利在这里兑现成复用红利。

### 9. 这一家的账与边界

收总账。收益侧：可训量千分之量级（教材锚点 0.134%），梯度与优化器显存同步瘦身，单卡可跑 7B 级微调；推理零增负（合并后与原模型逐位等价）；底座零改动，一份底座配任意多份 LoRA 文件，版本管理只管小文件；起点零扰动（A 置零初始化，DeltaW 从 0 长起）。成本与边界侧也有三笔：一是低秩假设本身——增量秩不够时效果封顶，出路是加 r、分段合并（ReLoRA）或干脆换方法，判断依据只能是实测；二是旋钮要试——挂哪些矩阵、r 取多少、α 怎么配，没有公式，省下的是单次训练的钱、付出的是试错轮次；三是合并与复用的治理——合并进底座的 LoRA 与未合并的小文件是两种交付形态，台账里必须写清哪份文件对应哪个底座版本、是否已合并，混了就会在上线时对不上账。与前两家并排：附加派赢在形态灵活但推理要付小额永续税，选择派赢在极简但受挑参上限约束，低秩派把两边的好处合在了一张可合并的增量上——它成为默认选项，不是靠某一项极端指标，是靠没有明显的短板。

## 代码验证（已运行）

自写脚本 `21-lora-verify.py`（标准库＋numpy，固定随机种子，可复现），做了七件事：按教材锚点复算 LoRA 参数账；验 A 置零初始化时增量严格为零、旁路与合并两种前向逐位等价；验增量数值秩不超过 r；在一个真实增量秩为 3 的合成任务上只训 A、B 并与全量微调对降损；演示 ReLoRA 多轮合并后总增量秩超过单个 r；验 AdaLoRA 正交正则在正交时为零；验 DoRA 列分解无损重构、并算出 LoRAHub 组合公式中的交叉项。

```python
W = W0 + alpha * (B @ A)   # LoRA 合并式，对应教材式 (4.9)：训完加回原权重，推理零增负
```

## 我的思考/应用

- **自家模型适配的默认起点，从这一篇起定为 LoRA。** 三家比较下来，它的短板最少：参数与显存账够低、推理零增负、底座零污染、文件可复用。以后任何「让开源模型学会我们某种文体或流程」的立项，默认先 LoRA 跑通评测，不过关再讨论加秩、换家族或全量。（成本：单卡小时级试错；收益：避开一上来就全量微调的显存与时间账；证据 B，教材参数与显存锚点＋本篇脚本复算互证，低秩假设在具体任务上是否成立仍须实测）
- **r 的试法要有纪律：从小到大、一档一评测。** r 是 LoRA 唯一的「容量旋钮」，实务上从 4 或 8 起步，每翻一档就留一条评测数，够用的最小档即定稿；无纪律地直接拉满 r，等于把省参数的红利又还回去。（成本：多两三轮小训练；收益：最终配置停在够用的最省档，且留有可查的选型依据；证据 C，我的工程判断，与本篇参数账的量级关系一致）
- **台账要把「合并态」写死。** LoRA 文件有两种交付形态：独立小文件（可拆可换）与合并进底座的整模型（部署简单但失去可拆性）。每份适配成果登记时必须写明底座版本、r 与 α、挂载矩阵、是否已合并——这条治理成本极低，漏了会在上线对账时成倍偿还。（成本：每份成果一行登记；收益：多任务并行与回滚时可追溯；证据 C，我的工程判断，源自第 19 篇起一以贯之的外挂治理口径）
- **攒 LoRA 要有仓库意识，复用先于重训。** LoRAHub 证明了组合旧模块加学一组系数，可以比从头训一份新的更便宜地拿下相近新任务；我们自己的适配文件从第一份起就按可复用规格存（任务描述、数据口径、评测分随文件走），攒到十份以上时，复用红利自然出现。（成本：每份文件多写一张说明卡；收益：新任务的边际适配成本递减；证据 B，教材式 4.15 与本篇交叉项验证说明组合机制成立，具体复用收益随任务相关性而变）
- **「增量低秩」是个可迁移的思维模型：改系统时先改少数主方向。** 提示词迭代、流程改造、参数调优都同理——先找到少数几个影响最大的方向集中改，其余保持不动，既省成本又可归因；若少数方向改完仍不够，再像 ReLoRA 那样分段累加，而不是一上来全盘重做。（成本：0，一次思路切换；收益：每次改动的成本与风险都压在少数方向上；证据 C，我的类比判断，机制来自本篇低秩假设与 ReLoRA 的分段合并）

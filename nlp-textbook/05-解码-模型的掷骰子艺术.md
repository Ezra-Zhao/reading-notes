## 一句话核心观点

模型每步只输出"下一个词的概率分布"，**解码策略决定怎么从这个分布里选词**——同样的模型，贪心、束搜索、调温度，写出来的东西天差地别；Transformer 解决了"怎么看"（注意力），解码解决的是"怎么选"。

## 详细解读

### 1. 问题设定：自回归生成的"指数爆炸"

自回归生成每步采样一个词，整句的概率是连乘：

$$P(w_{N+1:N+M}) = \prod_{i=N}^{N+M-1} P(w_{i+1}|w_{1:i})$$

想找到**全局最优**的那句话？词表 |D| 个词、生成 M 个词，共有 |D|^M 种组合——词表 5 万、生成 100 个词，就是 50000^100，宇宙原子总数才 10^80。**暴力搜索没门，只能用近似策略。** 下面五种策略，就是五种"近似 + 取舍"。

### 2. Greedy Search（贪心）：每步都拿第一名

$$w_{i+1} = \arg\max_{w \in D} o_i[w]$$

每步直接取概率最高的词。优点：快，每步一次前向传播；缺点：**短视**——只看眼前一步最优，不管整句全局。如下棋只看一步，很容易走进死胡同。我的玩具模型实测：贪心走出"长颈鹿是很长颈鹿远方有"——自己跟自己打转，典型的贪心近视。

### 3. Beam Search（束搜索）：手里攥着 b 条路

不只留一条路，保留 **b 个候选**（beam width）：每步把 b 条路各扩展出 |D| 个后续，按累积对数概率取前 b 条继续。b=1 时退化为贪心；b 越大，越接近全局最优——实测 beam 宽度 3 找到的序列总对数概率 −4.98，明显高于宽度 1 的 −7.14。

代价有二：计算量 × b；倾向"最安全"的答案——**概率最高的句子往往正确但无聊**（"今天天气不错"永远打败"今天云像打翻的牛奶"）。机器翻译等"求稳"任务标配束搜索，创意写作用它会写出正确的废话。

### 4. Top-K 采样：在前 K 名里掷骰子

只取概率最高的 K 个词，在里面按 softmax 重归一化后的概率**随机采样**。随机性带来多样性——同样的 prompt 每次输出不一样。但 **K 固定是硬伤**：模型很确定时（分布很尖），K 太大等于把垃圾词硬塞进候选，采出胡言乱语；模型没主意时（分布很平），K 又可能太小。书里图 1.9 专门画了 Top-K 的两种翻车：胡言乱语版和枯燥无味版——**固定的 K，应付不了千变万化的分布形状**。

### 5. Top-P / Nucleus 采样：骰子的面数自己会变

取**累积概率 ≥ p 的最小词集**，只在这个集合里采样。精妙之处在于**自适应**：模型确定时（概率集中在 2–3 个词），集合自动变小；模型犹豫时（概率摊平），集合自动变大。实测连续 6 步的候选集大小是 [11, 3, 10, 13, 13, 15]——骰子面数随分布实时伸缩。p 取 0.9–0.95 是今天大模型 API 的默认配置，**用一个超参数同时解决"确定时收敛、犹豫时发散"**。

### 6. Temperature（温度）：给分布调"对比度"

$$p(w) \propto \exp(o[w]/T)$$

T 是 softmax 的对比度旋钮：**T > 1 把分布拍平**（更大胆、更发散，冷门词也有机会）；**0 < T < 1 把分布压尖**（更保守、更确定）；**T → 0 退化为贪心**（实测 T=1e-6 的采样输出与 argmax 完全一致）。同一组 logits：T=3.0 写出"长远方四条地很树叶"（放飞自我），T=0.3 写出"长颈鹿有四条腿"（老实巴交）。温度可与 Top-K/Top-P 叠加使用——**先调温度定"性格"，再调 Top-P 定"边界"**。

## 手写代码与验证（已运行）

```python
import numpy as np

VOCAB = ["长颈鹿", "是", "有", "四条", "腿", "脖子", "很", "长", "吃", "树叶",
         "在", "草原", "上", "奔跑", "睡觉", "打架", "优雅", "地", "看着", "远方"]
V = len(VOCAB)

def fake_logits(history):
    """玩具 logits：给定 history 确定性输出（种子由 history 派生），保证可复现。"""
    seed = abs(hash(tuple(history))) % (2**31)
    z = np.random.default_rng(seed).normal(0, 1.0, V)
    if not history:
        z[VOCAB.index("长颈鹿")] += 4.0
    last = history[-1] if history else None
    if last == "长颈鹿":
        z[VOCAB.index("有")] += 3.0; z[VOCAB.index("是")] += 2.0
    if last == "四条":
        z[VOCAB.index("腿")] += 5.0
    if last == "有":
        z[VOCAB.index("四条")] += 3.5
    return z

def softmax(z, T=1.0):
    z = np.asarray(z, dtype=float) / T
    z = z - z.max()
    e = np.exp(z)
    return e / e.sum()

def greedy(history, steps):
    out = list(history)
    for _ in range(steps):
        out.append(VOCAB[int(np.argmax(fake_logits(out)))])
    return out

def beam_search(history, steps, width):
    beams = [(list(history), 0.0)]
    for _ in range(steps):
        cands = []
        for seq, lp in beams:
            p = softmax(fake_logits(seq))
            for w in range(V):
                cands.append((seq + [VOCAB[w]], lp + float(np.log(p[w] + 1e-12))))
        cands.sort(key=lambda x: x[1], reverse=True)
        beams = cands[:width]
    return beams

def sample_topp(history, steps, p, T=1.0, seed=0):
    r = np.random.default_rng(seed)
    out, sizes = list(history), []
    for _ in range(steps):
        z = fake_logits(out)
        order = np.argsort(z)[::-1]
        probs = softmax(z[order], T)
        cut = int(np.searchsorted(np.cumsum(probs), p)) + 1
        sizes.append(cut)
        cand = order[:cut]
        cp = probs[:cut] / probs[:cut].sum()
        out.append(VOCAB[r.choice(cand, p=cp)])
    return out, sizes
```

top-p=0.9 候选集大小: [11, 3, 10, 13, 13, 15]     # 集合大小随分布自适应

## 我的思考/应用

1. **调参实战手册**：写代码/做数学题 → T=0–0.3（接近贪心，少犯错）；写文案/头脑风暴 → T=0.7–1.0 + top_p=0.9。**temperature 定性格、top_p 定边界**，两个别同时往极端调。
2. **解码 ≠ 智能**：束搜索找到的是"模型认为最可能的句子"，不是"人最想要的句子"——这正是 RLHF/DPO 要修的 gap。解码策略再花，也弥补不了模型本身的价值观偏差。
3. **工程账**：greedy + KV cache 是推理最快的组合；beam search 计算和显存都 × b，线上服务默认用"采样 + 温度"而不是大 beam——**省下来的算力就是省下来的钱**。
4. **复读机问题**：确定性解码容易自我重复（实测 beam 也打出"四条腿四条腿"）——真实系统靠 repetition_penalty / frequency_penalty 压制。这是"曝光偏差"的表亲：训练时没见过自己犯错，推理时一错就循环。
5. **面试弹药**：手写 top-k/top-p 采样 20 行是 LLM 岗位常见考题；再深一层要能讲清"为什么 T→0 就是 greedy"（softmax 退化为 one-hot）。

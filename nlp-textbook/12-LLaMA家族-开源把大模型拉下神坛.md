# NLP 读书笔记（12）：LLaMA 家族——把同样的架构，拆开、抠细、免费发出来

> 来源：中文 NLP 教材（浙江大学），《Foundations of LLMs》讲义第二章 2.5.3 节
> 覆盖：书页码 76–82 · 本篇为 clean-room 重写，代码为自写示例并已运行验证

## 一句话核心观点

GPT 把王座坐稳之后，Meta 走了另一条路：**架构仍是 Decoder-only，不靠把参数堆得更大取胜，而是把每个零件抠细（RoPE、RMSNorm、SwiGLU、Pre-Norm、GQA），再用远超常规比例的数据去喂相对不大的模型，最后把权重开放出来。** 结果是小模型打赢大模型、开源生态在一个底座上长出满天繁星——LLaMA 证明了两件事：数据的力量可以压过参数的力量；开放本身，就是一种比闭源迭代更快的进化方式。

## 详细解读

### 1. 路线之争：GPT 拼规模同步放大，LLaMA 押注"小模型 + 大数据"

教材把两家的分野说得很直白（表 2.5）：GPT 的升级主线是参数和语料一起往上抬；LLaMA 则让参数规模相对克制，把力气压在语料规模上。三代的账摆在一起看最清楚：

| 模型 | 时间 | 参数量 | 语料规模 |
|---|---|---|---|
| LLaMA-1 | 2023.02 | 67 / 130 / 325 / 652 亿 | 约 5 TB |
| LLaMA-2 | 2023.07 | 70 / 130 / 340 / 700 亿 | 约 7 TB |
| LLaMA-3 | 2024.04 | 80 / 700 亿 | 约 50 TB |

注意第三行：参数档位几乎没动，语料涨到上一代的七倍。这背后是第 07 篇 Chinchilla 缩放定律的实操版——同样算力下，参数和数据要按比例配；但 LLaMA 又比 Chinchilla 更激进：它故意把小模型"喂过头"。我的验证代码算了 tokens/参数这笔账：GPT-3 约 1.7，接近 Chinchilla 最优的 LLaMA1-65B 约 21.5，而 LLaMA1-7B 约 149，LLaMA3-8B 高达约 1875。逻辑是成本结构变了：训练是一次性支出，推理是每一次调用都要付的账——为推理便宜而多花训练费，长期是划算的。权重以非商业许可向学术界开放这一点同样关键：它让全球研究者能站在同一个底座上改，生态效应在第 5 节兑现。

### 2. LLaMA-1（2023.02）：四个零件，把 Transformer 抠细

LLaMA-1 的骨架和 GPT 完全同构，创新全在零件级（教材图 2.16 对照图）。逐个拆：

**RoPE（旋转位置编码）替代绝对位置编码。** 原始 Transformer 给每个位置加一个固定的位置向量，位置信息是"贴"上去的。RoPE 换了思路：把查询和键向量按位置角度做二维子空间内的旋转，位置越远转得越多。妙处在数学结构：两个词的注意力分数只取决于它们的相对距离，不取决于各自站在第几位。我的代码验证了这一点——同一对向量，放在 (5,3)、(10,8)、(20,18) 三组位置上，内积完全相同（0.9834），且旋转不改变向量长度。它对长文本外推也更友好，今天几乎成了开源模型的标配。

**RMSNorm 替代 LayerNorm，并挪到 Pre-Norm 位置。** LayerNorm 做两件事：减均值中心化、除标准差缩放。RMSNorm 只保留缩放，用均方根做尺度，不减均值，计算更省，效果不打折——代码里同一组数过 RMSNorm 后均方根恰好归到 1.000，而均值不归零，方向被保留。放置位置学的是 GPT-3 的 Pre-Norm：归一化放在注意力和前馈的输入端，而不是输出端，训练更稳，深层也不容易炸。

**SwiGLU 替代 ReLU 前馈。** 普通前馈是一条直路：变换、ReLU、再变换。SwiGLU 把它改成两条支路：一路过 SiLU 激活当"内容"，另一路当"闸门"，两路逐元素相乘再投影回去——哪些信息放行、放行多少，由闸门逐维决定。代码里闸门值是连续的软开关，不是 ReLU 那种一刀切。代价是前馈参数多了一组矩阵，通常用缩小隐藏维度来找平总参数。

四个版本一字排开：7B（32 层、4096 维、32 头）、13B（40 层、5120 维）、32.5B（60 层、6656 维）、65B（80 层、8192 维、64 头）。语料约 5 TB，混了 Common Crawl、C4、GitHub、维基百科、古腾堡与 Books3、arXiv、StackExchange——公开来源为主，这也是它敢开放的底气之一。

### 3. LLaMA-2（2023.07）：数据扩到 7 TB，再把 RLHF 补上

第二代参数档位基本照旧（7B / 13B / 34B / 70B），动作在三处。一是语料扩到约 7 TB，覆盖的语言和领域更宽。二是对齐补课：先用大规模公开指令数据做有监督微调，再训奖励模型，用 PPO 加拒绝采样做 RLHF——就是第 11 篇 InstructGPT 那套三步，Meta 把它完整复刻到开源底座上，于是有了能对话的 Chat 版本。三是 34B 和 70B 上加了 GQA（分组查询注意力）。

GQA 值得单独算账，因为它解决的是推理时最疼的 KV 缓存。标准多头注意力里，每个查询头都配一对自己的键和值，生成时每多一个词，所有层的键值都要存着，序列一长，缓存比模型本身还吓人。GQA 让一组查询头共享同一对键值：头还是那么多，键值头数砍到几分之一。我的代码按 32 层、序列 1024、每头 128 维算：32 个 KV 头时缓存约 537 MB（fp16），GQA 砍到 8 组只剩约 134 MB，正好四分之一；极端的单组共享（MQA）只剩约 17 MB，但质量代价更大。GQA 就是中间那档：省得够多，质量掉得够少。

### 4. LLaMA-3（2024.04）：参数几乎没动，数据涨七倍，性能质变

第三代只出 8B 和 70B 两档，架构和二代几乎完全相同，只动了分词器：词表扩大到三倍量级。这一手对中文用户格外实在——词表太小时，一个汉字常被拆成多个 token，既费上下文又割裂语义；词表大了，完整语义单元被切开的概率下降，同样的文本 token 数更少，处理更快、连贯性更好。

真正的变量还是数据：约 50 TB，是二代的七倍多，其中代码数据占比可观以强化逻辑推理，非英文数据超过百分之五、覆盖三十多种语言。加上和二代同样的 RLHF，结果是教材给的那个刺眼对比：8B 版本在多项评测上超过 LLaMA2 的 70B 版本；70B 版本在多项任务上超过 GPT-4（按教材成书时的口径）。参数账一行没涨，性能账翻了一页——这是"数据的力量"最硬的一个实例，也是第 07 篇缩放定律在产品层面的回收：定律告诉你比例在哪，LLaMA3 告诉你把数据推到远超"最优比例"之后，小模型能把上限顶多高。

### 5. 衍生生态：开放底座上长出的三类繁星

教材把衍生模型分三类，这个分类本身就是开源价值的证据：

- **性能改进类**：Alpaca 用 GPT-3.5 生成的指令数据微调 LLaMA-1，小模型摸到接近 GPT-3.5 的指令遵循；Vicuna 改用 ShareGPT 上真实用户对话微调，主攻对话体验；Guanaco 用 QLoRA 把微调的显存和时间成本打下来，让普通人也能动手改大模型。
- **垂域任务类**：Code Llama 在 LLaMA-2 上灌代码数据，做生成、查错和优化；LawGPT 用三十万条法律问答做指令微调；GOAT 用脚本生成的数学题库练算术与解题；Cornucopia 用金融问答做中文金融适配。通用底座加垂域数据，就是一个领域模型，这条流水线被 LLaMA 跑通成了模板。
- **多模态类**：LLaVA 在 Vicuna 上接 CLIP 图像编码器加一个线性投影层对齐图文；MiniGPT-4 用 ViT-G/14 加 Q-Former 做图像编码，同样靠投影层完成跨模态对齐。文本底座没变，多接一个感官，就多一个模态。

三类合起来看：Meta 只发布了底座，成百上千的改进、适配和扩展由全球社区自费完成，再回流成整个生态的公共资产。这和闭源路线形成镜像：OpenAI 的迭代速度取决于一家公司，LLaMA 的迭代速度取决于所有使用者之和。

### 6. 与 GPT 对照收尾：两条路线的账本

教材表 2.8 把两家并排：GPT 从 1.17 亿参数、约 5 GB 语料起步，到 GPT-4 起参数和语料全部未公开；LLaMA 三代参数守在 652–700 亿的量级内，语料从约 5 TB 一路公开着涨到约 50 TB。一边是能力上限的探索者，靠规模和闭源服务变现；一边是可用性的普惠者，靠效率零件、数据强度和开放生态扩散。Decoder-only 这个共同祖先没有变，变的是"赢"的定义：一个赢在最强，一个赢在最多人能用、能改、能部署。下一篇离开 Transformer 本体，去看它的第一个挑战者：不用注意力、只用状态方程处理长序列的状态空间模型，以及 RWKV 和 Mamba。

## 我的思考/应用

- **选开源底座时，先看零件，再看参数。** RoPE、RMSNorm、SwiGLU、GQA 这四件套决定了长上下文、训练稳定性和推理成本，比参数表上的数字更贴近真实使用体验。以后评估一个开源模型，我的检查顺序改成：位置编码是什么、归一化放哪、KV 头怎么分组、词表对中文友不友好，最后才看跑分。这四项在模型卡里都写着，不需要等测评。（成本：0，评估习惯；收益：避免买到参数唬人、推理又贵又慢的模型；证据 B，零件与成本的关系是教材与代码实测结论）
- **"训练一次、推理无数次"的账，要搬进自己的工具选型。** LLaMA 故意把小模型喂过头，本质是把成本从高频的推理端挪到一次性的训练端。我的流水线是同构的：提示词模板、黄金示例库、审核清单都是一次性投入、每天反复调用的东西，在这些地方多花一倍时间打磨，回报会被调用次数放大；反过来，每次任务里临时纠结的判断，应该想办法沉淀成模板，让它只付一次。（成本：模板与示例库整理约半天；收益：每条日更线的边际制作成本持续下降；证据 C，方法迁移，成本结构与 LLaMA 的推理账同型）
- **GQA 的缓存账提醒我：长上下文不是免费的，它按层数乘序列长度收钱。** 用 API 时上下文塞得越满，延迟和费用越高，这和 KV 缓存的物理账是同一件事。对策已经明确：给模型的上下文只放与本步决策相关的材料，长文档先提炼再喂，历史对话滚动摘要而不是全量回放。（成本：0，流程纪律；收益：响应更快、额度消耗可控，70%、90% 预警线更不容易被无谓上下文吃掉；证据 A，缓存公式可算，已实测）
- **垂域路线被 LLaMA 生态验证成了模板，我的领域适配照抄这个结构。** 通用底座加垂域数据加指令微调，就是 LawGPT、Code Llama 的做法；映射到我的场景：通用的写作与审核底座不动，教会、汽修、投资三个垂域各自备一份术语表、黄金示例和判断清单，效果上就是"微调"，成本却只是文档。这也解释了为什么示例库要按垂域分开建，而不是攒一个大杂烩。（成本：每个垂域整理约 1 小时；收益：产出的领域准确度提升，且底座升级时垂域资产可直接迁移；证据 B，垂域衍生模型的公开结果）
- **开放的复利，值得在自己的内容战略里留一席。** Meta 放弃独占权重，换回全球社区的改进回流；对应到 GitHub 冲星战略，就是把笔记、速查表、模板真正开放出去，让使用者变成共创者——有人提 issue、有人翻译、有人补例子，这些回流比一个人闭门更新快。红线不变：开放的是 clean-room 产出和自有资产，客户与保密材料永不进这个池子。（成本：维护社区反馈的时间；收益：内容资产的迭代速度从单人变成网络；证据 C，战略类比，LLaMA 生态本身是 A 级实例）

# NLP 读书笔记（18）：PEFT 全景——只动一小撮参数

> 来源：中文 NLP 教材（浙江大学），《Foundations of LLMs》讲义第四章 4.1 节
> 覆盖：书页码 151–156（4.1 参数高效微调总览：下游任务适配的两条老路、三大家族分类、显存对照表 4.1）· 本篇为 clean-room 重写，例题与代码均为自编并已运行验证

## 一句话核心观点

**让一个训好的大模型适配新任务，原来只有两条路：不改参数、只改输入的上下文学习，和改全部参数的指令微调——前者便宜但有上限，后者有效但贵到一张好显卡都装不下。参数高效微调（PEFT）是第三条路：把原模型冻住，只训练一小撮参数——多则百分之几、少则万分之几——换来接近全量微调的效果。** 教材把现有方法收成三大家族：往模型里加新参数训的「附加派」、从原参数里挑一小撮训的「选择派」、把权重增量压成低秩矩阵训的「低秩派」。这一篇不细抠任何一家，先把地图画全：三家的分界不在名字，而在回答同一个问题——那一小撮可训参数，到底从哪来。

## 详细解读

### 1. 这一节的位置：从「不动参数」到「动一小撮」

第三章整章都在讲不动参数的手艺：Prompt 写得再好、示例编排再巧，模型本身一克没变。3.5 收尾时立过一条分界线：编排能解决的用编排，解决不了的就得动参数。第四章就是来兑现这句话的。但「动参数」不等于「动全部参数」——4.1 开篇先把适配下游任务的两条老路摆出来，PEFT 正是站在两条老路的毛病上长出来的：取指令微调的「真改模型」、躲开它的「全改一遍」。

### 2. 老路一：上下文学习——不训，但有天花板

第一条路是第三章的主角：把指令和少量示例（Demonstrations）拼进 Prompt，靠模型现场看例子现学现卖。它零训练成本、切换任务只换一段文字，但教材在这一节把它的账算明了：示例要占上下文窗口，任务越复杂示例越长，能留给真正输入的空间就越少；效果还随示例的选法、排法大幅摆动，稳定性欠账；更根本的是，它只是在「调用」模型已有的能力，教不会它一件真正没学过的新本事。适合打样和轻任务，重任务压不住。

### 3. 老路二：指令微调——真改，但贵

第二条路是把大量「指令—回答」数据喂回去做有监督微调，让模型把「听指令办事」练成本能。教材点了这条路的家底：数据集一侧有 Flan、P3 这类把大量现成任务改写成指令格式的大合集；数据造法一侧有 Self-Instruct（第 17 篇拆过）、InstructWild 这类让模型半自动造数据的流水线；GPT-3.5、GPT-4 这一代对话模型的成型，都走过这条路。效果是真的好，代价也是真的硬：全量微调要为每一个参数存梯度和优化器状态，教材以 LLaMA2-7B 为例给出口径——显存需求在 60GB 量级，单张 24GB 的 RTX 4090 根本带不动；而且每适配一个新任务，就得多存一整份模型副本，任务一多，存储先爆。

### 4. PEFT 的定义：冻住大象，只牵耳朵

参数高效微调的定义朴素到一句话：冻结预训练模型的绝大部分参数，只训练一小部分，适配目标照样达成。它赌的是一个观察：下游适配需要改动的东西，其实没有参数总量看上去那么多——通用能力在预训练里已经长好了，适配要补的只是「往哪儿偏一点」。补的方式不同，就分出了三大家族；共同点是可训参数从 100% 掉到个位数百分比甚至更低，梯度与优化器状态只跟着这一小撮走，显存与存储的账立刻翻篇（第 6 节算细账）。

### 5. 三大家族：那一小撮参数从哪来

教材图 4.2 的分类法干净利落（后续 4.2–4.4 各领一节）：

**附加参数方法（Additional Parameters Methods）**：原参数一个不动，在模型里或输入端外挂一小块新参数，只训这块。代表：Adapter-tuning（层间插入小瓶颈模块）、Prompt-tuning（输入端拼一段可训的软提示）、Prefix-tuning（各层注意力前加可训前缀）。同节还点到 Proxy-tuning，它是个例外：不往模型里塞参数，而是用一对同源大小模型（一个微调过、一个没微调）的输出差，在解码时调制没微调的大模型——「附加」的不是结构参数，而是一个外部的差值信号。这一家除 Proxy-tuning 外的共同气质：模块化最强，摘下来模型就还原，装上就是新任务。

**参数选择方法（Parameter Selection Methods）**：不加新东西，从原有参数里挑一小撮解冻来训，其余继续冻。代表：BitFit（只训偏置，教材后文给的口径是只占总参数的 0.08%–0.09%）、Child-tuning（每一步只更新随机抽中的一个子网络）、FishMask（按 Fisher 信息量挑「重要」的参数训）。共同气质：一分新参数不加，挑得准不准就是全部手艺。

**低秩适配方法（Low-Rank Adaptation Methods）**：不直接改原权重，给每张要改的权重矩阵外挂一个低秩增量——把增量拆成两个瘦长矩阵相乘，只训这两个。代表：LoRA 本尊，外加自适应分配秩预算的 AdaLoRA、一次训练兼容多个秩的 DyLoRA、把权重拆成幅度与方向再调的 DoRA。共同气质：增量可以训完合并回原权重，推理时零额外开销，这是它后来成主流的大半原因（合并机制留到 LoRA 专篇细拆）。

我的验证脚本把这十一个方法按「动的是什么」逐一分诊，与教材分类逐项对上。

### 6. 显存账：表 4.1 是这一节的实锤

光说「省」没用，教材表 4.1 给了在 80GB 的 A100 上的实测对照（LoRA 对全量微调）：bigscience 的 T0_3B，全量要 47.14GB GPU 显存，LoRA 只要 14.4GB；12B 的 mt0-xxl 和 7B 的 bloomz-7b1，全量微调直接 OOM（显存溢出，80GB 都装不下），LoRA 分别用 56GB 与 32GB 装下了；三者的 CPU 内存都在 3GB 上下，没拉开差距。我的脚本按 Adam 口径复算了同一笔账：可训参数每个要背约 16 字节（权重＋梯度＋一阶与二阶动量），7B 全量训练态约 112GB（未计激活），与「80GB 装不下」对得上；同一模型换 LoRA 口径——冻结底座只以 bf16 存权重（每参数 2 字节，约 14GB），只训 0.5% 的参数背那 16 字节——训练态落到约 14.5GB（未计激活）。两个场景的差别要说清：省下的大头不是优化器状态打折，而是 99.5% 的参数从「要背 16 字节」降成「只背 2 字节」。消费级显卡从「门外」变「门内」，这就是 PEFT 把微调从机房拉回个人桌面的全过程。当然要留一句实话：脚本是口径估算，表 4.1 是实测，两者对上的是量级，不是小数点。

### 7. 为什么只动一小撮够用：低秩的赌注

三大家族里最反直觉的是低秩派：凭什么一张权重矩阵的「修改量」能压成两个瘦矩阵？通行解释是：适配增量本身的有效维度并不高——真正要调的方向就那么几个，其余方向近似不动。我的脚本把这个赌注做成了对照实验：构造一个由 8 个主导方向生成的近低秩增量，秩取 8 的低秩分解捕获了它 99.7% 的能量，而参数只用了满秩的十六分之一；换成满秩噪声增量，同样的秩只能捕获 5.8%——赌注当场露馅。结论要说准：LoRA 不是「怎么压都不亏」，它赢在真实适配增量大多近低秩这个经验事实上；哪天任务需要的是满秩大改，它就得加秩、加覆盖面，或者让位给全量微调。这也是选型的第一性问题：先判断这个任务要模型「偏一点」还是「换个人」，再挑家族。

### 8. PEFT 的另一面：省下来的账，换个地方还

教材这一节的主调是立地图、算优势，我把工程上的三笔反账钉在这里，免得后文细拆各家时丢了全局。一是**上限**：可训参数越少，能塞进去的新能力越有限，个别任务上 PEFT 与全量的差距仍在，差距大小随任务与底座而变，不能一概说「无损」。二是**管理**：一个底座配几十个适配器，省的是存储，费的是版本管理——哪个适配器配哪个底座版本、哪份数据训的，必须有台账，否则省下的显卡钱会赔进排障时间。三是**选型**：三大家族加上各自的超参数（秩多大、插哪层、训哪部分），组合空间不小，「高效」的是参数，不是决策——小样本先行试错仍是纪律（证据 C，我的工程判断；教材本节未展开这三笔账）。

## 代码验证（已运行）

```python
def adam_gb(n_params):
    # fp32 权重 4B + fp32 梯度 4B + Adam 一阶/二阶动量各 4B
    return n_params * 16 / 1e9
```

几点说明：参数账里 Prompt-tuning 的 20×1024＝20,480，与教材后文 Prompt-tuning 一节给 T5-XXL 的口径（只训约两万个参数）正好互证；显存估算是 fp32 训练态口径，未计激活值与碎片，真实工程数随框架与精度策略浮动，只对量级负责；低秩实验的「近低秩增量」由 8 个方向人工构造，是机制演示不是真实微调数据，真实增量的近低秩性是 LoRA 原论文的实验结论，本篇只演示「若近低秩则压缩成立」这一半逻辑。

## 我的思考/应用

- **我们自己的模型适配，先 PEFT 后全量，顺序写死。** 以后任何「拿开源模型改一个自用版本」的活，默认先 LoRA 试：单卡能跑、一个适配器几十 MB 量级、训坏了删掉重来不伤底座；只有 PEFT 试出明确上限证据，才升级全量评估。（成本：LoRA 试错一轮为单卡数小时量级；收益：避开全量微调的显存与存储门槛，试错成本降一个数量级；证据 B，教材表 4.1 实测＋本篇脚本复算互证）
- **适配器就是我们的「技能包」形态：一个底座，N 个小包。** 审稿、拆书、话术这类风格与任务适配，天然对应「底座不动、适配器分工」——每个适配器配一张卡片记清底座版本、训练数据来源与用途，照第 8 节的管理账执行。这与 GPTs 把 Prompt 打包成产品是同构的，只是这一回打包的是参数。（成本：每个适配器一张卡片的登记纪律；收益：任务切换从「换模型」变「换小包」，存储与回滚都轻；证据 C，我的工程判断，与教材三大家族的模块化结论一致）
- **选型先答一道判断题：这个任务要模型偏一点，还是换个人？** 偏风格、偏格式、偏领域口径——PEFT 的主场；要塞进成体系的新知识、新能力——先怀疑 PEFT 不够，别在秩上无限加码硬顶。这道题答错，后面所有调参都是白烧。（成本：0，立项时的一次判断；收益：避开「低秩硬顶满秩任务」这类最常见的微调烂尾；证据 B，本篇低秩对照实验的直接推论）
- **显存账要自己会算，别等 OOM 才学。** 本篇的 16 字节/参数口径是粗账，但够在立项时挡住「拿 24GB 卡训 7B 全量」这类一眼假的排期。任何训练类任务开工前先用这本账过一遍：可训参数多少、训练态多少、激活另留多少，写进任务书再动手。（成本：五分钟计算；收益：排期与硬件决策有据可依，不靠试错撞墙；证据 A，计算口径可复算，脚本已实测演示）
- **BitFit 的 0.08% 是个提醒：先试最省的那档。** 三大家族里选择派最不起眼，但「只训偏置就能办成的事」若先被 LoRA 大动干戈办了，参数账就亏了。适配试错的顺序按可训量从小到大排：偏置→软提示→低秩→全量，每档留评测数，不过关才升档。（成本：多一两轮小试；收益：最终方案大概率停在够用的最省档；证据 C，我的工程判断，参数口径来自教材）

## 视频脚本要点（动画短片用）

1. 开场钩子："一个七十亿参数的大模型要学新本事，常规做法是把七十亿个参数全部重练一遍——光显存就要一百多 GB，桌上的显卡连门都进不去。这一篇讲的办法是：只动其中百分之一，效果却差不多。"
2. 冻住大象动画：一头大象形状的模型被冰封在整块冰里，工人在它耳朵边贴上一小块可拆卸的补丁，补丁亮起学习进度条，冰面纹丝不动——"大象不动，只训补丁。这就是参数高效微调。"
3. 三家分店动画：同一条街开出三家改衣店——第一家在衣服外缝口袋（附加派），第二家只改原有纽扣的位置（选择派），第三家拿一条瘦长的布带斜穿整件衣服、松紧全靠它（低秩派）——"改法不同，回答的是同一个问题：那一小撮要动的地方，到底从哪来。"
4. 显存天平动画：天平左盘放上写着 112GB 的砝码堆、轰然砸穿桌面，右盘只放 14.5GB 的小堆、稳稳停在桌面上，旁边一张 24GB 的显卡从门外探进头来——"全量微调把显卡挡在门外，PEFT 把它放了进来。"
5. 结尾钩子："三家之中最省的只动万分之八的参数，最红的却另有其人——下一篇拆附加派：不碰模型本体，只在输入口塞二十个'虚拟词'，就能把 110 亿参数的大模型调教好。"

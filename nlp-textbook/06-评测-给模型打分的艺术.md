## 一句话核心观点

模型写得好不好，不能靠"感觉"——**评测就是给模型打分的尺子**：内在评测（困惑度）量"模型对自己输出有多确定"，外在评测（BLEU/ROUGE）量"生成结果和参考答案有多像"，而新一代评测（BERTScore/G-EVAL）干脆请更强的模型来当裁判；**但每把尺子都有盲区，选尺子本身就是一门学问**。

## 详细解读

### 1. 先分清两种评测：看"内功"还是看"战绩"

- **Intrinsic Evaluation（内在评测）**：不看下游任务，直接量语言模型本身的概率质量——给定的句子，模型觉得"顺"还是"别扭"。优点是便宜、快、跟任务无关；缺点是"模型觉得顺"不等于"人觉得好"。
- **Extrinsic Evaluation（外在评测）**：把模型放到具体任务里（翻译、摘要、对话），看产出和参考答案的差距。更接近真实价值，但贵、慢，还受参考答案质量拖累。

### 2. Perplexity（困惑度 PPL）：内在评测的头牌

公式长这样（N 个词的测试句）：

$$PPL = \exp\left(-\frac{1}{N}\sum_{i=1}^{N}\log P(w_i|w_{<i})\right)$$

直觉：模型给测试句的每个词都打个分（概率），把这些概率取对数平均再取指数。**模型越"确定"，困惑度越低**——完美预测时 PPL=1，瞎猜时 PPL≈词表大小。困惑度本质上是交叉熵的指数形式，量的是"模型分布"和"真实分布"差多远。

但它有个著名毛病：**低困惑度 ≠ 写得好**。一个只会复读训练集的模型困惑度可以极低，写出来的东西却毫无用处。困惑度是"必要非充分"——太高了一定不行，低了不代表行。

### 3. BLEU：精确率导向，"说的话有多少是对的"

BLEU 最早为机器翻译设计，核心是**修正 n-gram 精确率**：候选译文里的每个 n-gram，去参考译文里"报销"——但同一个 n-gram 最多只能报销"参考译文里出现过的最大次数"（防止"我我我我我"刷分）。再乘以**简短惩罚**：候选比参考短太多要扣分（防止只说半句拿高分）。最后把 1~4 元文法的精确率做几何平均。

BLEU 的盲区很实在：①**对词序不敏感**（"猫喜欢鱼"和"鱼猫喜欢" unigram 精确率一样）；②**短句容易得 0 分**（trigram 一项为 0，几何平均直接崩盘）；③**同义不同词不认**（"喜欢"vs"爱"算错）。书里引了一句很妙的评论：BLEU 可能有罪，但参考答案也未必无辜——**参考译文本身就不是唯一的金标准**。

### 4. ROUGE：召回率导向，"该说的说了多少"

ROUGE 为摘要任务而生，和 BLEU 镜像：BLEU 问"候选里有多少在参考中出现过"（精确率），ROUGE 问"参考里有多少被候选覆盖了"（召回率）。几个变体：

- **ROUGE-N**：n-gram 召回率，N 越大对词序越敏感；
- **ROUGE-L**：用最长公共子序列（LCS）算，不要求连续，奖励"大意对了"；
- **ROUGE-S**：skip-bigram，允许中间跳词，介于两者之间；
- **ROUGE-W**：给连续匹配加权。

一句话记忆：**BLEU 奖"准"（别说错话），ROUGE 奖"全"（别漏要点）**。写摘要漏了关键句，ROUGE 会罚你；写翻译添油加醋，BLEU 会罚你。

### 5. BERTScore：请 BERT 来当"语义裁判"

n-gram 匹配太死板——"喜欢"和"爱"明明一个意思，BLEU/ROUGE 都判错。BERTScore 的思路：把候选和参考的每个词都过一遍 BERT，拿到**上下文相关的词向量**，然后算两两余弦相似度做"最优配对"：候选每个词找参考里最像的（Precision 方向），参考每个词找候选里最像的（Recall 方向），再合成 F1。**同义词、换说法，第一次被公平对待了。** 代价：要跑一遍 BERT，又贵又慢。

### 6. G-EVAL：让 GPT-4 当主考官

最新的路子是"LLM as a Judge"：直接让 GPT-4 这类强模型给生成结果打分。G-EVAL 的做法很讲究——不是扔一句"你打个分"，而是给考官一份**结构化考卷**：任务描述（这是什么任务）+ 评分标准（分几个维度、每档什么样）+ 评分步骤（用思维链 CoT 让考官先写推理再给分）。实测表明，带 CoT 的"先想后评"比直接打分更接近人类裁判。书里还提了 InstructScore，是同一家族的另一实现。

但"AI 给 AI 打分"有个躲不开的质疑：**考官自己的偏见怎么办？** 模型倾向给"像自己文风"的输出打高分、给长回答打高分——裁判也是运动员培养出来的。所以 G-EVAL 这类方法今天的定位是"便宜好用的初筛"，**关键决策还是要人看一眼**。

## 手写代码与验证（已运行）

```python
import math
from collections import Counter

def ngrams(tokens, n):
    return [tuple(tokens[i:i + n]) for i in range(len(tokens) - n + 1)]

# ---------- 1. Perplexity：玩具 bigram 模型 + 加一平滑 ----------
corpus = [["猫", "喜欢", "鱼"], ["狗", "喜欢", "骨头"], ["猫", "追", "蝴蝶"]]
bigram_counts, unigram_counts = Counter(), Counter()
for sent in corpus:
    for w in sent:
        unigram_counts[w] += 1
    for a, b in zip(sent, sent[1:]):
        bigram_counts[(a, b)] += 1
V = len(unigram_counts)

def bigram_prob(prev, w):
    return (bigram_counts[(prev, w)] + 1) / (unigram_counts[prev] + V)

def perplexity(sentence):
    log_sum = sum(math.log(bigram_prob(a, b))
                  for a, b in zip(sentence, sentence[1:]))
    return math.exp(-log_sum / (len(sentence) - 1))

print("== Perplexity ==")
for s in [["猫", "喜欢", "鱼"], ["猫", "喜欢", "骨头"], ["鱼", "吃", "猫"]]:
    print(" ".join(s), "-> PPL = %.3f" % perplexity(s))

# ---------- 2. BLEU 风格：修正 n-gram 精确率 + 简短惩罚 ----------
def modified_precision(candidate, references, n):
    cand_ng = ngrams(candidate, n)
    max_ref = Counter()
    for ref in references:
        for g, c in Counter(ngrams(ref, n)).items():
            max_ref[g] = max(max_ref[g], c)      # 报销上限：防"我我我"刷分
    cc = Counter(cand_ng)
    clipped = sum(min(c, max_ref[g]) for g, c in cc.items())
    return clipped / max(len(cand_ng), 1)

def bleu_like(candidate, references, max_n=2):
    ps = [modified_precision(candidate, references, n)
          for n in range(1, max_n + 1)]
    closest = min((len(r) for r in references),
                  key=lambda L: abs(L - len(candidate)))
    bp = 1.0 if len(candidate) >= closest else math.exp(1 - closest / len(candidate))
    geo = math.exp(sum(math.log(max(p, 1e-9)) for p in ps) / max_n)
    return bp * geo

refs = [["猫", "喜欢", "吃", "鱼"], ["猫", "爱", "鱼"]]
print("\n== BLEU-like (1-2 gram) ==")
for cand in [["猫", "喜欢", "吃", "鱼"], ["猫", "喜欢", "鱼"],
             ["鱼", "猫", "喜欢"], ["狗", "追", "蝴蝶"]]:
    print(" ".join(cand), "-> %.3f" % bleu_like(cand, refs))

# 短句 trigram 陷阱演示
print("max_n=3 时 '猫 喜欢 鱼' -> %.4f (trigram=0 拉崩几何平均)"
      % bleu_like(["猫", "喜欢", "鱼"], refs, max_n=3))

# ---------- 3. ROUGE-N 风格：n-gram 召回率 ----------
def rouge_n(candidate, references, n):
    cand = Counter(ngrams(candidate, n))
    match = sum(sum(min(cand[g], c)
                    for g, c in Counter(ngrams(r, n)).items())
                for r in references)
    total = sum(sum(Counter(ngrams(r, n)).values()) for r in references)
    return match / max(total, 1)

print("\n== ROUGE-N recall ==")
for cand in [["猫", "喜欢", "鱼"], ["猫", "喜欢", "吃", "鱼", "和", "虾"]]:
    print(" ".join(cand), "-> ROUGE-1 = %.3f, ROUGE-2 = %.3f"
          % (rouge_n(cand, refs, 1), rouge_n(cand, refs, 2)))
```

## 我的思考/应用

- **多模型互审就是"G-EVAL 平民版"**：他定的规矩"校对一律多 AI 一起"——让 Gemini 审 OpenAI 写的文案，本质就是用强模型当裁判。G-EVAL 的经验可以直接抄：**别只说"你审一下"，要给"评分维度+分档标准+先写理由再下结论"**，审稿质量立刻上一个台阶。
- **BLEU 奖"准"、ROUGE 奖"全"——内容生产两个都要**：动画脚本不能有事实错误（BLEU 思维：搭电顺序、扭矩数据，一个都不能错）；讲道改写不能漏要点（ROUGE 思维：三大部分、六类应用，一个不能少）。以后审稿 checklist 可以分这两栏打分。
- **TTS 幻觉质检的思路**：配音出英文幻觉循环（"transic talk…"）时，模型其实是对那段文本"不确定"——困惑度高的位置就是幻觉高发区。以后可以对配音文案先跑一遍困惑度扫描，**高困惑度的词提前换词**，而不是等合成出来再返工。
- **评测的终极提醒**：自动指标再精致也替代不了"人看一眼"——视频发布前他坚持"豆豆自审+他点头"，和论文里"G-EVAL 之后仍需人类终审"是同一个道理。**尺子是筛子，不是法官。**

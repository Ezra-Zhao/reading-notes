# NLP 读书笔记（09）：BERT 家族——遮住词，猜全句

> 来源：中文 NLP 教材（浙江大学），《Foundations of LLMs》讲义第二章 2.3 节（Encoder-only 代表模型）
> 覆盖：书页码 49–59 · 本篇为 clean-room 重写，代码为自写示例并已运行验证

## 一句话核心观点

上一篇说 Encoder-only 是"全看"的理解型架构，这一篇讲它最出名的一家人：**BERT 靠一招"随机遮住约 15% 的词、让模型用左右两边把词猜回来"（掩码语言建模 MLM），再加一个"猜下一句是不是真的下一句"的任务（NSP），成了第一个真正通用的双向预训练模型**；后面三个改进版各治一个病——RoBERTa 证明 BERT 只是"没训够"（架构不动、数据和步数拉满就更强），ALBERT 把参数砍到约九分之一（词嵌入因式分解加跨层共享），ELECTRA 把"只在遮住位置算损失"的浪费改掉（逐词验真假，每个位置都出信号）。**理解这一家，就理解了"预训练"三个字最初是怎么落地的。**

## 详细解读

### 1. 先补一课：从"一个词一个向量"到"一个词一句话一个向量"

教材 2.3.1 节先交代 Encoder-only 为什么值得单独立传。Word2Vec、GloVe 这类老式词向量有个死穴：一个词永远对应一个固定向量——"银行"在"去银行存钱"和"坐在河银行边"里是同一个向量，可意思完全不同。Encoder-only 的编码器读的是整句话，同一个词在不同句子里会得到不同的表示，教材称之为上下文词向量（Contextual Embedding）。这一步看着小，却是分水岭：词义不再是词典里查出来的，而是当场根据上下文算出来的。BERT 家族做的事，就是把这种"当场算词义"的模型，先在海量无标注文本上预训练好，再拿去干具体的活。

### 2. BERT 本体：不大，但站位极准

BERT 是 Google 在 2018 年 10 月拿出的 Encoder-only 代表作，结构就是一摞原装 Transformer 编码器，没有任何花哨改动，两个规格（教材 2.3.2 节）：

- **BERT-Base**：12 层、隐藏维度 768、12 个注意力头，总参数约 1.1 亿；
- **BERT-Large**：24 层、隐藏维度 1024、16 个注意力头，总参数约 3.4 亿。

预训练语料是 BookCorpus（约 8 亿词）加英文维基百科（约 25 亿词），合计约 33 亿词、十几 GB 纯文本。按今天的眼光看，这个体量小得可爱——但它证明了一件大事：**不用给文本打任何人工标签，光靠"自己出题自己答"，就能把语言规律压进参数里。** 出题方式就是下面两个任务。

### 3. 输入长什么样：两个特殊记号撑起全部下游任务

BERT 的输入序列里塞了两个特殊 Token，后来成了整个家族的通用语法：

- **[CLS] 放在句首**：它没有自己的词义，任务是"汇总全句"。编码器跑完之后，这个位置的输出向量就被当作整段文本的代表向量——做分类、做句对判断，都读它。
- **[SEP] 放在句尾和两句之间**：当输入是两个句子拼起来时，用它把两句隔开，模型再靠分段信息区分"哪部分是第一句、哪部分是第二句"。

配合词向量、分段向量、位置向量三者相加当输入，BERT 一次前向就能吃下"单句"和"句对"两种形态——问答、推理、匹配，全被装进同一个输入格式里。下游用法顺理成章：分类任务接 [CLS] 的输出加一个分类头；抽取式问答、命名实体识别这类要逐词判断的任务，就读每个 Token 自己的输出。**预训练只训一个模型，微调时换个小头就能干新活**，这正是第 07 篇说的"预训练加微调"范式第一次完整落地。

### 4. 任务一 MLM：遮住词猜回来，为什么还要留 10% 不遮

MLM（Masked Language Model，掩码语言建模）的做法拆开看只有三步：

1. 在每个样本里随机挑出约 15% 的 Token 作为"考题"；
2. 被挑中的位置里，80% 真的换成特殊记号 [MASK]，10% 换成一个随机词，10% 保持原样不动；
3. 只在这些被挑中的位置上算损失（其余位置的标签一律忽略），让模型根据左右全部上下文把原词猜出来。

第 2 步的 80/10/10 是全篇最值得细品的设计。为什么不全换成 [MASK]？因为下游微调和真实使用时，文本里根本不会出现 [MASK] 这个记号——如果预训练时模型只学会"看到 [MASK] 才认真猜词"，一到真实文本就水土不服，这叫预训练与微调的分布不匹配。留 10% 随机词，是逼模型对每个位置都保持警觉（这个词可能是错的，得靠上下文验一遍）；留 10% 原样，是逼它哪怕输入看着没问题，也要把表示学扎实。我的验证代码把这一整套原样跑了一遍：22 个词的句子选中了 3 个位置，恰好 [MASK]、随机词、保持原样各一例（见下节）。

代价也写在明面上：**一句话只有约 15% 的位置出训练信号**，其余 85% 只做"上下文背景板"。上一篇算过这笔账——信号密度远低于 Decoder-only 的逐词预测。这是 BERT 学得"精"的原因，也是它训得"费"的原因，后面的 ELECTRA 就是冲着这条来改的。

### 5. 任务二 NSP：猜两句话是不是真邻居

BERT 的第二个预训练任务是 NSP（Next Sentence Prediction，下一句预测）：把两个句子拼成一个样本，50% 的样本里第二句就是原文里紧跟的第一句，另 50% 里第二句是从别处随机抽来的，让模型读 [CLS] 的输出做二分类——"这两句是真连续，还是假拼凑"。出题意图是让模型学会句子之间的关系，服务问答、自然语言推理这类句对任务。

这个任务的后续命运很有戏剧性：RoBERTa 复现时发现，把 NSP 直接删掉、改成一次喂更长的连续文本，效果反而更好；ALBERT 则认为 NSP 太简单（随机抽的句子话题都对不上，模型靠猜话题就能蒙对），换成了更难的 SOP（Sentence Order Prediction，句子顺序预测）——两句一定来自同一段原文，只考"顺序是正的还是被调换的"，逼模型真去学连贯性而不是话题。**一个任务从标配到被删、被改，只用了两年——预训练任务没有神圣不可动摇的，全看消融实验说话。**

### 6. 改进版一 RoBERTa：什么都没改，只把训练拉满

RoBERTa（Facebook AI，2019 年 7 月）是三个改进版里最"不讲理"的一个：模型结构和 BERT 几乎一字不改，改的全是训练配方——

- **数据从十几 GB 拉到约 160 GB**：在 BERT 的书和维基之外，加了新闻、网页文本和故事语料；
- **训得久得多**：训练步数大幅增加，批量也更大；
- **动态掩码**：BERT 是在数据准备阶段一次性把词遮好，同一句话每次被读到遮的都是同一批词；RoBERTa 改成每次喂入时现遮，同一句话能以很多种遮法被反复考；
- **删掉 NSP**，改喂长连续文本（见上一节）。

结果是 Base 和 Large 的参数量和 BERT 基本一致（约 1.2 亿和 3.5 亿），成绩却全面反超。RoBERTa 的教训和第 07 篇 Chinchilla 的故事是同一个：**很多时候不是模型不行，是没训够。** 在怀疑架构之前，先问一句数据量、步数、批量这三样拉满了没有。

### 7. 改进版二 ALBERT：参数砍到九分之一的两把刀

ALBERT（Google，2019 年 9 月）治的是另一个病：BERT 参数太多、太占显存。它动了两把刀：

- **词嵌入因式分解**：BERT 的词嵌入是一张词表大小乘隐藏维度的大矩阵（30000 乘 768，约 2304 万参数）。ALBERT 先把词压进一个低维空间（768 降到 128），再升回隐藏维度，两张小矩阵相乘代替一张大矩阵——参数降到约 394 万，我的代码验算过，压缩约 5.85 倍。道理是词本身的信息量不需要占满 768 维，上下文那部分维度留给上面的层去算。
- **跨层参数共享**：BERT 的 12 层各有各的参数，ALBERT 让所有层共用同一套参数，反复用 12 次。总参数因此骤降：ALBERT-Base 只有约 0.12 亿，大约是 BERT-Base 的九分之一；就算堆到 XXLarge（约 2.2 亿），也比同级 BERT 省得多。

再加上用 SOP 换掉 NSP（第 5 节），ALBERT 用少得多的参数和显存拿到了和 BERT 相当甚至更好的成绩。它证明的是：**参数量不等于能力，参数的"用法"才是。** 这条对今天在小设备、端侧跑模型的场景依然成立。

### 8. 改进版三 ELECTRA：别猜词了，逐词验真假

ELECTRA（Google Brain，2020 年 3 月）的改动最伤筋动骨：它认为 MLM 最大的浪费，就是 85% 的位置不出信号。它的解法是借鉴 GAN 的双模型结构：

- 先训一个小号生成器（本身是个小 BERT），照 MLM 的老办法把遮住的词猜出来填回去——它猜的词通常语法通顺、但不一定是原词，比如把"性格"猜成"体格"，句子读着也通；
- 再训一个判别器，逐词判断"这个位置是原词，还是被生成器换过的"（Replaced Token Detection，替换词检测）；
- 判别器才是最后要用的模型，生成器训完就退场。

关键账在信号密度上：判别器在**每一个位置**上都有对错可学，同样一句话，训练信号是 MLM 的约 6 到 7 倍（我的代码里 22 个词的句子是 3 对 22，约 7.3 倍）。所以 ELECTRA 用远小于 BERT 的算力就能追平甚至超过它。这一招的思想含量很高：**把"生成正确答案"（难、信号稀）改造成"判断真假"（易、信号密），往往是更划算的学习方式**——不光对模型成立。

### 9. 一张表收束这一家

| 模型 | 时间 | 参数量 | 预训练任务 | 它证明的那一件事 |
|---|---|---|---|---|
| BERT | 2018.10 | 1.1 亿 / 3.4 亿 | MLM + NSP | 双向预训练加微调这条路走得通 |
| RoBERTa | 2019.07 | 1.2 亿 / 3.5 亿 | 动态 MLM（删 NSP） | BERT 只是没训够，配方比结构重要 |
| ALBERT | 2019.09 | 0.12 亿起 | MLM + SOP | 参数砍到约九分之一，能力基本不掉 |
| ELECTRA | 2020.03 | 0.14 亿起 | RTD 逐词验真假 | 换个任务定义，信号密度能涨约 7 倍 |

回到上一篇的架构之争收个尾：Decoder-only 赢走了"生成"这块最大的蛋糕，但只要任务是理解——分类、打标、检索、抽取——这一家的编码器至今仍是性价比的默认答案：一次前向出整句表示，不用逐词生成，部署便宜、延迟低。下一节 2.4 讲的 Encoder-Decoder 代表模型（T5、BART），走的则是第三条路。

## 代码验证（已运行）

自写脚本 `09-bert-mlm-verify.py`（numpy 加标准库，手写，无教材代码，固定随机种子可复现），做了四件事：按 15% 概率选中考题位置并执行 80/10/10 处理；用 -100 标签演示"只在选中位置算损失"；对比 MLM 与 ELECTRA 式 RTD 的信号密度；验算 ALBERT 词嵌入因式分解的参数账。

```python
import numpy as np

rng = np.random.default_rng(42)
tokens = ["水豚", "性格", "十分", "温顺", "且", "没有", "攻击性", "它", "只", "吃",
          "水草", "和", "树叶", "游客", "喂", "它", "水果", "时", "它", "慢慢", "走", "过来"]
n = len(tokens)

# MLM 遮词: 约 15% 被选中; 选中者 80% 换 [MASK], 10% 换随机词, 10% 保持原样
selected = rng.random(n) < 0.15
labels = np.full(n, -100)  # -100 = 不计损失, 其余位置只做上下文
for i in np.where(selected)[0]:
    labels[i] = tok2id[tokens[i]]  # 只有选中位置保留真实标签
# loss = 只对 labels != -100 的位置求交叉熵平均 (脚本中完整实现)

# ALBERT 词嵌入因式分解: V x H -> V x E + E x H
V, H, E = 30000, 768, 128
bert_emb = V * H            # 23,040,000
albert_emb = V * E + E * H  # 3,938,304
```

**实际运行输出**（节选，已验证）：

```

  ELECTRA / RTD: 22 个位置算 loss (100%)

ALBERT 词嵌入参数账 (词表 V=30000, 隐藏 H=768, 低维 E=128):
  BERT  直接嵌入 V x H       : 23,040,000 参数
  ALBERT 两步嵌入 V x E + E x H: 3,938,304 参数
```

几点说明：脚本里的 logits 用固定种子的随机数加一点人为优势模拟编码器输出，只为演示损失的掩码口径，不代表真实模型水平，能复现的结论是"哪些位置计损失、信号差几倍、参数差几倍"这三笔账；80/10/10 在小样本上只是概率，本次运行恰好三种各出一例，纯属种子运气好；真实 BERT 的遮词是在分词后的子词（subword）粒度上做的，脚本按词演示，逻辑一致。

## 我的思考/应用

- **客服机器人的"听懂"环节，就该用这一家。** 雨刷 WhatsApp 客服真正烧钱的是生成回复，但它前面还有一层便宜活：判断客户这句话是问价格、问适配车型、还是要售后，顺带把车型和故障关键词抽出来。这类分类加抽取用 Encoder-only 的小模型（或同类嵌入模型）一次前向就能干完，又快又便宜，没必要每个请求都去敲生成式大模型。分工定死：理解层用编码器思路，生成层才用 Decoder-only。（成本：小模型 API 或本地部署，单次成本远低于生成调用；收益：高频简单请求不走大模型，账单和延迟一起降；证据 B，教材结论加工程共识）
- **内容流水线的自动打标和查重，是现成的编码器活。** 拆书笔记、讲道稿、视频脚本每天都在产，靠人工归类迟早乱套。用 [CLS] 式整段表示做相似度查重（防重复选题）、做主题分类（自动进对应仓库和目录），是 BERT 这套表示方法最经典的用法，我的 GitHub 内容矩阵可以直接接。（成本：0 到低，嵌入调用或本地小模型即可；收益：素材库从"堆文件"变成"可检索"，复用率上去；证据 B）
- **MLM 的 80/10/10，是"训练要像实战"的最好教材。** BERT 不敢把考题全换成 [MASK]，因为考场和真实世界长得不一样——这条对我的英语口语训练和客服测试同样成立：口语练习如果全是干净的标准句，到了真打 WGU 电话时一句口音和插话就崩；客服机器人测试如果全是规范提问，客户第一句方言加错别字就露馅。对策同款：训练和测试样本里主动掺 10% 到 20% 的"脏样本"（口误、错别字、半句话），别等真实场景来教做人。（成本：0，只是改样本配比；收益：上线翻车率下降；证据 C，类比迁移，原理在 ML 侧是 A 级共识）
- **ELECTRA 的思路可以搬进校对流程：逐段验真假，比整篇重写便宜。** 我的多 AI 交叉校对现在多是"读一遍、挑毛病"，接近判别器模式而不是生成器模式——这篇给了它一个理论靠山：判断"这段对不对"的信号密度和效率，天然高于"重新写一段"。以后审稿提示词就按 RTD 的逻辑设计：逐句过、每句必须表态"原样通过还是被换过味"，不许只给总体印象。（成本：0，改提示词；收益：审稿漏检率下降，尤其能抓"读着通顺但词被偷换"这类错；证据 C，方法迁移）
- **ALBERT 的因式分解提醒我：先压一层，再升上去。** 把 768 维的活先压到 128 维办，是很实用的工程美学——我的视频流水线和数据处理脚本也一样：原始素材先转成紧凑的中间表示（大纲、元数据表、转写稿），再进昂贵环节（生成、渲染、发布），不要拿着几个 GB 的原文件全程跑。这正是他定的"材料转成最小空间紧凑表示"的做法，模型这边算是给了个同款注脚。（成本：0，流程习惯；收益：存储和处理时间都省；证据 C，类比；因式分解本身的参数账是 A 级可验算）

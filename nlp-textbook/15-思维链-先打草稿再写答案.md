# NLP 读书笔记（15）：思维链——让模型先打草稿，再写答案

> 来源：中文 NLP 教材（浙江大学），《Foundations of LLMs》讲义第三章 3.3 节
> 覆盖：书页码 115–121（3.3 思维链：按部就班、三思后行、集思广益）· 本篇为 clean-room 重写，例题与代码均为自编并已运行验证

## 一句话核心观点

上一篇的上下文学习只教模型照着示例给答案，这一篇再往前一步：**示例里不光给答案，还把"怎么想"一步一步写出来，模型就学会了先生成中间推理、再落最终答案——这就是思维链（Chain-of-Thought, CoT）。** 它要解决的是一个很具体的尴尬：多步推理题（算术、逻辑、常识推理）在标准提示下，模型再放大、曲线也几乎是平的；把推理过程摊开写，能力才被放出来。围绕这条链，教材分出三大流派：**按部就班**——把链生成出来（零样本触发、自动构造示例）；**三思后行**——链不够，要搜索（把推理展开成树、成图，边走边评估边回溯）；**集思广益**——一条链不可信，就采样多条链投票（自一致性）。三派的共同点是：不改一个参数，用更多的推理时计算，换更高的可靠性。

## 详细解读

### 1. 为什么需要思维链：平坦的缩放曲线

第 07 篇讲缩放定律时埋过一个伏笔：很多任务上模型越大越强，但多步推理是个例外。教材 3.3 开头点明：用标准提示（只给题、直接要答案）做推理任务时，性能随模型规模放大的收益很快变平——参数堆上去了，题还是做不对。原因不难理解：一步直答等于要求模型在一次前向里把多步运算全"心算"完，中间结果没地方放、错了也没机会改。CoT 的改法极朴素：让模型把中间步骤像草稿纸一样写出来，每一步的结果都变成白纸黑字的 token，后面的计算可以踩着它往下走。推理从"心算"变成了"笔算"，这正是它有效的机制。

### 2. 思维链是什么：示例里连过程一起给

CoT 最早的形态是少样本提示的一种变体（第 14 篇的 ICL）：示例的答案部分不再只有一个结论，而是一段连贯的推理——先算什么、得到什么、再算什么、所以答案是什么。新问题来了，模型模仿这个形状，先续写自己的推理链，再续写结论。教材的演示题都是多步增减类应用题，推理链就是把每一步的加减和中间小计写全。两个要点别漏：一，CoT 是涌现能力的又一例，小模型给链也学不会、甚至被链带乱，规模够大才稳定受益（与第 07 篇呼应）；二，链本身成了可检查的中间产物——算错在哪一步，第一次变得能指出来，这是后面"三思后行"能评估每一步的前提。

### 3. 教材的分类：一条链的三种活法

教材用一张总图把 CoT 家族收成三支，我按自己的话复述。**按部就班**管"生成"：怎样让模型老老实实一步一步把链走完，代表是 Zero-Shot CoT 与 Auto-CoT。**三思后行**管"搜索"：一条直链走错一步就全错，于是把推理展开成分叉的结构，每步生成多个候选、先评估再选路、走不通就回溯，代表是思维树（ToT）与思维图（GoT）。**集思广益**管"共识"：同一道题采样出多条不同的链，对最终答案多数投票，代表是自一致性（Self-Consistency）。三支是递进关系：先能走，再会找，最后靠人多。

### 4. 按部就班之一：Zero-Shot CoT——一句话触发词

最省事的版本连示例都不给。做法分两段：第一段，在问题后面缀一句触发语（教材用的是"让我们一步一步思考"这个意思的英文短语），模型就顺着它把推理链续写出来；第二段，再用一句固定收尾（"因此，最终答案为："这个句式）把答案从链里抽出来，方便程序自动判分。它揭示了一件有意思的事：多步推理的"程序"本来就装在模型里，缺的只是一个启动信号——触发词不提供任何新知识，只是把生成模式从"直答"切换成"笔算"。代价也要记清：零样本链的质量完全押在模型自身，链里算错一步，后面照样全错，而且没有示例兜底格式，抽取环节更容易出岔。

### 5. 按部就班之二：Auto-CoT——示例链自动生产

少样本 CoT 的痛点是示例链要人一条一条手写，费工、还容易把个人偏好写进去。Auto-CoT 把这道工序自动化：先把题库里的问题按语义聚类（保证挑出的示例覆盖不同题型，而不是全是同一类），再对每个簇的代表问题用 Zero-Shot CoT 让模型自己生成推理链，生成结果直接当示例，拼成少样本提示。思路和第 14 篇的选例纪律是一脉的：代表性优先。它的风险也写在明处：自动生成的链可能本身就算错，错的示例等于亲手教错——所以聚类保证多样性之外，实务上还要对生成链做过滤或抽检。我的验证脚本没有复刻聚类，只演示了它依赖的底座（触发词两阶段）。

### 6. 三思后行：思维树与思维图——把推理变成搜索

直链的死穴是不可回头。思维树（Tree of Thoughts, ToT）把每一步从"一个想法"改成"多个候选想法"：模型在每个节点生成几条可能的下一步，再用提示让模型给每个候选打评估（教材 24 点例子里用的是"可以、可能、不可能"三档），然后按搜索算法（广度或深度优先）挑最有希望的路走下去，此路不通就回溯换路。24 点是它的招牌演示：四个数凑 24，第一步选错运算，后面再努力也凑不出来，必须允许试错与退回。思维图（Graph of Thoughts, GoT）再放宽一层：想法之间不只是树状分叉，还可以合并、聚合、互相修正、形成回环——比如把两条半成品推理合成一条。代价同样直白：节点每多分叉一层，调用次数指数级涨，ToT/GoT 是拿推理时算力换可靠性，只值得用在链式 CoT 反复翻车、且答案可验证的硬题上。

### 7. 集思广益：自一致性——多条链投票

自一致性（Self-Consistency）的假设是：同一道题，正确的推理路径往往不止一条，而错误各有各的错法。做法是把解码调成采样模式（第 05 篇的温度采样正好派上用场），让带 CoT 的提示跑出多条不同的推理链，抽出每条链的最终答案，多数投票定胜负——学名叫对推理路径做边缘化，只保留答案的共识。我的验证脚本把这件事做成了可数的演示：五条路径四条殊途同归、一条中途滑步，投票 4 比 1 把正确答案保了下来。边界同样要钉住：它只对"答案唯一、能对齐投票"的任务成立（算术、选择、分类），开放生成没有"票"可投；而且多条链同源同模型，系统性误解会一起错、投票也救不了——投票治随机滑步，不治认知盲区。

### 8. 这一节与前后章的咬合

往回看：CoT 是 ICL 的特例（示例内容从"答案"升级为"过程"，第 14 篇结尾钩子正是此句）；它的采样投票直接调用第 05 篇的随机解码；它的涌现门槛是第 07 篇缩放定律的注脚。往后看：3.4 的 Prompt 技巧会讲何时该用 CoT、何时别用（简单任务硬上 CoT 只是白烧 token）；而当链的生成与搜索都压榨完，就轮到第四章动参数了。顺序还是那句老话：**先把不花钱的推理时技巧用尽，再考虑花钱改模型。**

## 代码验证（已运行）

自写脚本 `15-cot-verify.py`（仅标准库，固定数据，可复现），做了四件事：自编多步算术题上直答捷径与逐步 CoT 的对照，并演示中间一步出错的传播；Zero-Shot CoT 的触发与抽取两阶段拼装；五条路径的自一致性投票；24 点的迷你树搜索（生成候选、递归回溯）。

```python
def cot_solve(ops):
    state, trace = 0, []
    for name, delta in ops:
        state = delta if name == "start" else state + delta
        trace.append(f"{name}: 当前 = {state}")
    return state, trace
# 题：47 个起，卖出 19、新烤 25、卖出 31 -> 22
```

**实际运行输出**（节选，已验证）：

```
=== 1. 直答 vs CoT ===
直答捷径(只看头尾): 16  (正确答案 22) -> 错
CoT 最终: 22 -> 对
中间一步差 1 的 CoT: 23 -> 错（链越长，越要逐步验算）
投票结果: {22: 4, 23: 1} -> 多数答案 22（4/5 票），与真值一致: True
=== 4. ToT 迷你版（24 点：4, 4, 10, 10）===
搜索展开节点数: 7424
找到的解: (((10*10)-4)/4) = 24.0
```

几点说明：直答捷径是玩具模拟，只演示"不展开中间状态时容易滑步"这个方向，不代表真实模型的错误形态；树搜索是穷举回溯版，只借用了 ToT 的生成-评估-搜索骨架，真实 ToT 的候选生成与评估都由大模型用提示完成；自一致性的五条路径为手写构造，投票逻辑（抽答案、计数、取多数）是真实可用的。

## 我的思考/应用

- **给各生产线的审稿与拆解提示默认加"先列依据、再下结论"的链式格式。** 本质就是 Zero-Shot CoT 的触发思想：结论前先写中间判断，错误能定位到步，比只给结论可查得多。（成本：每条输出的 token 约增两三成；收益：返工时只重跑出错的那一步，不整单重做；证据 B，教材与 CoT 原始研究口径一致，幅度因任务而异）
- **关键数字与结论走"自一致性"平民版：换一种算法或一句话复述，独立再算一遍，两边对上才交付。** 我做战报、账目、参数核对时的双路复核就是这个原理——不一定要采样五次，两条真正独立的路径就已经能挡掉大部分随机滑步。（成本：关键结论多花一次复核时间；收益：挡掉单路径算错这类低级事故；证据 B，投票机制对随机错误有效、对系统性错误无效，边界见正文第 7 节）
- **遇到"一步错、全盘错"的硬核查（法条链、装配顺序、搭电顺序这类），思路从链升级到树：先列多个候选步骤、逐个评估安全性、再定稿。** 这是 ToT 的人工版，也是既有安全审稿纪律的同构升级。（成本：硬核查耗时上升，只用在安全与法律类高 stakes 项；收益：避免直链思维里第一步定错方向还浑然不觉；证据 C，我的工程经验判断）
- **CoT 不是免费的，也不是万能的：简单任务不用链，开放写作不投票。** 链长直接等于 token 账单；分类、抽取这类一步任务套长链纯属浪费，生成类任务没有唯一答案、自一致性无从下手。用不用链，先看任务是不是"多步且可验"。（成本：0，选型纪律；收益：省推理成本、防伪精确；证据 B，教材 3.4 的适用性讨论与本节机制的直接推论）
- **给 Ezra 的一句话翻译：让 AI 先打草稿，等于让它笔算不让它心算。** 他本人指挥模型时，复杂问题加一句"一步一步来、先写过程再给答案"，就是本篇最核心的一招，零成本、立竿见影。（成本：0，沟通习惯；收益：他直达模型的复杂问答一次到位率上升；证据 B，Zero-Shot CoT 机制的直接推论）

## 视频脚本要点（动画短片用）

1. 开场钩子："一道三步的算术题，心算的学霸栽了，拿草稿纸一步一步写的普通人对了——大模型也一样：不让它打草稿，它就只能心算。"
2. 草稿纸动画：一道多步题飘进来，模型直接蹦出一个答案、打上红叉；镜头重来，它先在草稿纸上写下第一步的小计、踩着小计写第二步、第三步，最后圈出答案打上绿勾——"中间步骤写出来，推理就从心算变成了笔算。这叫思维链。"
3. 触发词特写：同一道题，问法只多了一句"让我们一步一步思考"，屏幕上的输出立刻从一行答案变成一段推导——"它什么新知识都没学，只是被一句话切换了模式。"
4. 分叉路口动画：一条直链走到死胡同、整条变红作废；画面一转，路口分出三条岔路，每条路口都立着一块牌子（可以、可能、不可能），走错的那条自动退回路口换一条——"一条链是赌博，一棵树是搜索。"
5. 投票动画：五张草稿纸同时算同一道题，四张圈着同一个答案、一张圈了另一个，五张叠在一起，多数的那个透出来——"错法各不相同，对法殊途同归。下一篇：把这些技巧收成规范——Prompt 技巧篇。"
